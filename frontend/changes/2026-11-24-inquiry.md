# 문의사항 — 프론트 수정 요청 (2026-11-24)

- 백엔드: spec `.beaver/output/spec/inquiry/inquiry-spec.md` · plan `.beaver/output/plan/inquiry/inquiry-plan.md` · 커밋 2026.11.24
- 반영 순서: 백엔드 배포 먼저 — 모두 새 API 라 지금 화면은 그대로 동작한다. 새 화면은 백엔드가 배포된 뒤 붙인다.

## 바뀐 이유
이용자가 업체나 바로방(운영)에 문의할 통로가 없었다. 이용자는 카테고리를 골라 문의하고 답변을 보며, 업체 관리자는 자기 업체 문의를, 관리자는 업체 대상이 아닌(바로방) 문의를 답변하고, 부적절한 문의는 상세에서 한 건씩 블라인드한다(사용자 요청).

## 영향 화면
새 화면이 생긴다 — 주소 · 배치는 프론트가 정한다(키는 screens.md 에 없으니 이름으로 적는다).
- 이용자: **문의 등록**(업체 이름 검색 · 카테고리 고르기 · 동의 항목 체크), **내 문의 목록**(카테고리 · 상태 거르기), **내 문의 상세**(답변 · 블라인드 안내) — 진입은 U10 마이페이지 · U2 업체 상세(그 업체로 문의) 등 프론트가 정한다
- 업체 관리자(M): **문의 목록**(카테고리 · 상태 · 검색어) · **문의 상세**(답변 쓰기 · 고치기 · 블라인드 · 해제)
- 관리자(A): **바로방 문의 목록** · **문의 상세**(같은 기능 — 업체 대상이 아닌 문의만)

## API 변경
| 구분 | 메서드 · 주소 | 방식 | 바뀐 점(요청 · 응답 · 실패 · 로그인) |
|---|---|---|---|
| 추가 | `GET /api/v1/user-service/discovery/store-search?keyword=` | 동기 · 로그인 없음 | 문의할 업체 이름 검색 — 상호명 부분 일치, 영업 중 · 영업중지 업체를 상호명 순 최대 20건. `{list: [{store_id, store_name, address, latitude, longitude, image_url}]}` — 위경도는 지도에서 위치 확인용, `image_url` 은 대표 사진 1장(없으면 null). 검색어가 비었거나 50자를 넘으면 400(`keyword`) |
| 추가 | `GET /api/v1/user-service/inquiry/category` | 동기 · 로그인 없음 | 문의 카테고리 목록 `{list: [{inquiry_category_id, inquiry_category_name}]}` — 보일 순서(예약 · 결제/환불 · 객실/시설 · 출입/QR · 회원/계정 · 입점 · 기타). **이용자 화면과 업체 관리자 · 관리자 화면이 같이 쓴다** |
| 추가 | `POST /api/v1/user-service/inquiry` | 큐(SSE) · 이용자 | 문의 등록 `{store_id?, inquiry_category_id, title, content}` — `store_id` 를 빼면 바로방 문의. done `{inquiry_id}`. 탈퇴 · 지운 · 없는 업체는 failed 404 `업체를 찾을 수 없습니다.`. 검증 400 — 카테고리 없음 `카테고리를 선택해주세요.` · 허용값 밖 `카테고리가 올바르지 않습니다.` · 제목 100자 · 내용 2000자 · 업체 ID 형식. **선언 안 된 필드(동의 값 등)를 보내면 400** — 동의 값은 보내지 않는다 |
| 추가 | `GET /api/v1/user-service/inquiry?inquiry_category_id=&inquiry_state_id=&page=&size=` | 동기 · 이용자 | 내 문의 목록 — 카테고리 · 상태 거르기(**값을 빼면 전체**), 최신순, 블라인드된 문의도 나온다. `{list: [{inquiry_id, store_id, store_name, inquiry_category_id, inquiry_category_name, title, inquiry_state_id, inquiry_state_name, answered_at, created_at}], pagination}` — 바로방 문의는 `store_id` · `store_name` null. 허용값 밖 400 |
| 추가 | `GET /api/v1/user-service/inquiry/:inquiry_id` | 동기 · 이용자 | 내 문의 상세 — 목록 칸 + `content` · `answer_content`(답변 전 null). 남의 문의는 404 `문의를 찾을 수 없습니다.` |
| 추가 | `GET /api/v1/admin-service/inquiry/mine?inquiry_category_id=&inquiry_state_id=&keyword=&page=&size=` · `GET /api/v1/admin-service/inquiry?…` | 동기 · `/mine` 매니저 · 그 밖 관리자 | 문의 목록 — 업체 관리자는 소속 업체 문의, 관리자는 업체 대상이 아닌(바로방) 문의만. 카테고리 · 상태(빼면 전체) · 검색어(제목 · 내용, 100자). `{list: [{inquiry_id, user_id, user_nickname, inquiry_category_id, inquiry_category_name, title, inquiry_state_id, inquiry_state_name, answered_at, created_at}], pagination}`. 업체 관리자의 업체가 탈퇴 · 삭제됐으면 404 `소속 업체를 찾을 수 없습니다.` |
| 추가 | `GET /api/v1/admin-service/inquiry/mine/:inquiry_id` · `GET /api/v1/admin-service/inquiry/:inquiry_id` | 동기 · `/mine` 매니저 · 그 밖 관리자 | 문의 상세 — 목록 칸 + `store_id` · `content` · `answer_content` · `answer_user_name`(마지막으로 답변한 계정 이름) · `blinded_at`. 범위 밖(다른 업체 · 업체/바로방이 다른) 문의는 404 |
| 추가 | `PUT /api/v1/admin-service/inquiry/mine/:inquiry_id/answer` · `PUT /api/v1/admin-service/inquiry/:inquiry_id/answer` | 큐(SSE) · `/mine` 매니저 · 그 밖 관리자 | 답변 `{answer_content}`(2000자) — 문의당 1개, 다시 보내면 통째로 고쳐 쓰고 답변완료. done data 없음. 블라인드된 문의는 failed 400 `블라인드된 문의에는 답변할 수 없습니다.`, 범위 밖 404 |
| 추가 | `PATCH /api/v1/admin-service/inquiry/mine/:inquiry_id/blind` · `PATCH /api/v1/admin-service/inquiry/:inquiry_id/blind` | 큐(SSE) · `/mine` 매니저 · 그 밖 관리자 | 블라인드 — 본문 없음, 한 건. done data 없음. 이미 블라인드면 failed 400 `이미 블라인드된 문의입니다.`, 범위 밖 404. 답변은 지우지 않는다 |
| 추가 | `PATCH /api/v1/admin-service/inquiry/mine/:inquiry_id/unblind` · `PATCH /api/v1/admin-service/inquiry/:inquiry_id/unblind` | 큐(SSE) · `/mine` 매니저 · 그 밖 관리자 | 블라인드 해제 — 본문 없음, 한 건. 답변이 있던 문의는 답변완료, 없던 문의는 접수로 돌아간다. done data 없음. 블라인드가 아니면 failed 400 `블라인드된 문의가 아닙니다.`, 범위 밖 404 |

상태 값: `RECEIVED` 접수 · `ANSWERED` 답변완료 · `BLIND` 블라인드(이름은 응답의 `inquiry_state_name`). 매니저 토큰으로 관리자 경로를 부르면(또는 그 반대) 401.

## 화면 구성과 쓰는 API 의 변경
- **문의 등록(이용자)**
  - 대상 고르기: "바로방에 문의" 또는 "업체에 문의". 업체는 `GET …/discovery/store-search` 로 이름을 검색해 고른다 — 결과마다 상호명 · 주소 · 대표 사진(`image_url`, 없으면 기본 그림)을 보여 주고, **지도를 눌러 위치(`latitude` · `longitude`)를 확인**할 수 있게 한다. 고른 업체의 `store_id` 를 등록에 넣는다(업체 상세에서 들어오면 그 업체를 미리 골라 둔다).
  - 카테고리: `GET …/inquiry/category` 를 불러 고르게 한다 — **화면에 하드코딩하지 않는다**(백엔드에서 항목이 늘면 저절로 나온다). 필수.
  - **동의 항목 체크(사용자 결정 2026-11-24)**: 등록 버튼 전에 동의 항목(개인정보 수집 · 이용 동의 등 — 문구는 프론트가 정한다)을 모두 체크해야 등록할 수 있게 한다. **동의 값은 서버로 보내지 않는다**(서버는 받지도 저장하지도 않는다 — 보내면 400).
  - 등록은 큐 경로 — `accepted` → `done`/`failed`/`pending` SSE. done 이면 내 문의 상세(`inquiry_id`)로 보낸다.
- **내 문의 목록(이용자)**: 카테고리 칩(카테고리 목록 API) · 상태 칩 **전체 · 접수 · 답변완료 · 블라인드**. "전체" 는 그 query 를 빼고 부른다. `pagination` 은 거른 결과 기준. 바로방 문의는 업체 대신 "바로방" 으로 보인다(`store_name` null).
- **내 문의 상세(이용자)**: 제목 · 카테고리 · 대상 · 내용 · 답변(있으면 `answer_content` · `answered_at`). **상태가 `BLIND` 면 상세에 "스팸/반복성 문의로 블라인드 된 문의입니다." 를 띄운다**(사용자 결정 2026-11-24 — 내용은 그대로 보인다).
- **문의 목록(업체 관리자 `/mine` · 관리자)**: 카테고리 · 상태(전체 · 접수 · 답변완료 · 블라인드) · 검색어(제목 · 내용). 목록에서 여러 건을 골라 한꺼번에 처리하는 기능은 **없다**.
- **문의 상세(업체 관리자 · 관리자)**: 작성자 닉네임 · 카테고리 · 내용 · 답변. 답변 입력란 하나 — 답변이 없으면 "답변 등록", 있으면 같은 API 로 "답변 수정"(통째로 바꾼다). **블라인드 · 해제 버튼은 상세에 하나만**(상태가 `BLIND` 면 "블라인드 해제", 아니면 "블라인드") — 부적절한(스팸 · 도배) 문의를 보고 한 건씩 처리한다(사용자 결정 2026-11-24). 블라인드 상태에서는 답변 입력을 막는다(서버도 400). 처리 뒤 상세를 다시 불러 상태를 맞춘다.
- 업체 관리자는 `/mine…` 경로, 관리자는 `/mine` 없는 경로를 쓴다. 카테고리 목록은 관리 화면도 이용자 쪽 `GET /api/v1/user-service/inquiry/category`(로그인 없음)를 쓴다.

import {IsNotEmpty, MaxLength} from 'class-validator';

/**
 * 업체 이름 검색 query (문의할 업체 고르기) — 상호명 부분 일치. 쿼리 값은 문자열이다.
 */
export class DiscoveryStoreSearchDto {
    // 검색어 — 상호명 부분 일치 (50자까지)
    @MaxLength(50, {message: '검색어는 50자 이내로 입력해주세요.'})
    @IsNotEmpty({message: '검색어를 입력해주세요.'})
    keyword: string;

    /**
     * @param data 요청 쿼리 — 빠진 검색어는 빈 문자열(검증에서 걸린다)
     */
    constructor(data?: Partial<DiscoveryStoreSearchDto>) {
        this.keyword = data?.keyword ?? '';
    }
}

/**
 * 업체 이름 검색 항목
 */
export class DiscoveryStoreSearchItemResultDto {
    // 업체 ID — 문의 등록의 store_id
    store_id: string;

    // 상호명
    store_name: string;

    // 주소
    address: string;

    // 위도 (WGS84) — 지도에서 위치 확인
    latitude: number;

    // 경도 (WGS84) — 지도에서 위치 확인
    longitude: number;

    // 대표 사진 주소 (업체 사진 첫 장 — 공개 주소), 없으면 null
    image_url: string | null;
}

/**
 * 업체 이름 검색 결과 — 영업 중 · 영업중지 업체, 상호명 순 최대 20건. 주소 · 위경도 · 대표 사진 1장 포함(사용자 결정 2026-11-24)
 */
export class DiscoveryStoreSearchResultDto {
    // 업체 (상호명 순, 최대 20건)
    list: DiscoveryStoreSearchItemResultDto[];
}

contracts/inquiry/dto/inquiry.dto.ts
```ts
import {IsIn, IsNotEmpty, IsOptional, Matches, MaxLength} from 'class-validator';
import {INQUIRY_CATEGORY_IDS} from '../inquiry.constants.js';

/**
 * 문의 등록 (이용자) — 업체를 고르면 그 업체, 안 고르면 바로방 문의. 동의 항목은 프론트가 등록 전에 체크한다(서버로 보내지 않는다).
 */
export class InquiryDto {
    // 문의할 업체 ID (업체 이름 검색으로 고른다) — 없으면 바로방 문의
    @IsOptional()
    @Matches(/^[a-f0-9]{32}$/, {message: '업체 ID가 올바르지 않습니다.'})
    store_id?: string;

    // 카테고리 ID (항목은 GET /api/v1/user-service/inquiry/category)
    @IsIn(INQUIRY_CATEGORY_IDS, {message: '카테고리가 올바르지 않습니다.'})
    @IsNotEmpty({message: '카테고리를 선택해주세요.'})
    inquiry_category_id: string;

    // 제목 (100자까지)
    @MaxLength(100, {message: '제목은 100자 이내로 입력해주세요.'})
    @IsNotEmpty({message: '제목을 입력해주세요.'})
    title: string;

    // 내용 (2000자까지)
    @MaxLength(2000, {message: '내용은 2000자 이내로 입력해주세요.'})
    @IsNotEmpty({message: '내용을 입력해주세요.'})
    content: string;
}

/**
 * 문의 등록 결과
 */
export class InquiryResultDto {
    // 문의 ID
    inquiry_id: string;
}
```

import {IsIn, IsOptional} from 'class-validator';
import {PaginationDto, PaginationResultDto} from '@app/common/dto/pagination.dto.js';
import {INQUIRY_CATEGORY_IDS, INQUIRY_STATE_IDS} from '../inquiry.constants.js';

/**
 * 내 문의 목록 query (이용자) — 카테고리 · 상태 거르기(없으면 전체) · 페이지. 블라인드된 문의도 나온다.
