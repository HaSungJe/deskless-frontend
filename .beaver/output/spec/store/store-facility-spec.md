# 업체 편의시설 — 켜고 끄기 · 보기 · 검색필터

## 한눈에

- **무엇을** 업체 관리자가 편의시설 7개(편의점 · 카페 · 온천 · 반려동물 동반 · 식사 제공 · 배달 음식 · 주차)를 켜고 끄면, 이용자는 업체 상세에서 보고 지도의 "검색필터"(거리 · 객실 · 편의시설을 한 팝업에서)로 고르며, 관리자는 업체 상세에서 본다.
- **왜** 업체 단위로 내세울 편의시설이 없었다(백엔드 수정 요청 `frontend/changes/2026-11-24-store-facility.md` — 필터 항목 주소가 바뀌어 프론트와 함께 나간다). 지도 위 거리 칩 줄은 팝업으로 옮겨 지도를 넓게 쓴다(사용자 요청).
- **범위 밖** 관리자가 편의시설을 바꾸기(API 없음), 편의시설 아이콘 그림, 객실 옵션(방 2개 이상 · 샤워실 · TV · PC) 변경, 거리 값(5 · 10 · 20 · 50km · 제한 없음) 변경.

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 지도 검색필터 | 버튼 하나 → 팝업(거리 한 줄 · 객실 · 편의시설 체크) → 적용 때 한 번 검색 | 9건 |
| 2. 업체 상세 편의시설 | 켜진 편의시설만 글자 칩, 없으면 칸 숨김 | 3건 |
| 3. 내 업체 설정 편의시설 탭 | 스위치 7개 → 7개 모두 저장(큐) → 다시 읽기 | 1건 |
| 4. 관리자 업체 상세 편의시설 | 켜진 편의시설 이름만 보기 | 0건 |

## 1. 지도 검색필터 — `PAGE /`

**동작 흐름**

1. **버튼 보이기** — 지도 위 거리 칩 줄 대신 "검색필터" 버튼 하나만 둔다. 글자는 지금 거리 · 고른 수를 함께 보인다(아래 계산 규칙).
2. **팝업 열기** — 버튼을 누르면 "검색필터" 팝업이 열리고, 처음 열 때 한 번 새 주소(`detail-filter`)로 체크 항목을 읽는다.
   - 항목을 못 읽었으면 → 받은 문구 · 다시 열어 달라는 안내, 거리는 그대로 고를 수 있다
3. **고르기** — 맨 위 "거리" 한 줄(5 · 10 · 20 · 50km · 제한 없음)에서 하나, 아래 "객실" · "편의시설" 묶음(아래 계산 규칙)에서 여럿을 고른다.
   - "초기화"를 누르면 → 거리 20km · 체크 모두 해제(적용을 눌러야 검색)
   - "닫기"를 누르면 → 아무것도 바뀌지 않는다
4. **적용** — 고른 거리와 고른 키(묶음과 상관없이 항목 순서대로 쉼표)로 마지막으로 멈춘 지도 중심에서 한 번 검색한다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `radius_km` | ✓ | 고른 거리 — `5` · `10` · `20` · `50` · `ALL`(제한 없음), 처음 `20` |
| `detail_filter` | | 고른 항목 키를 쉼표로(예: `has_pc,has_hot_spring`) — 고르지 않으면 보내지 않는다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 팝업을 열어 거리 10km · "PC"(객실) · "온천"(편의시설)을 고르고 적용한다 | 항목 읽기 1번(새 주소) → "거리" · "객실" · "편의시설" → 업체 검색 1번(`radius_km` 10 · `detail_filter` `has_pc,has_hot_spring`) → 팝업 닫힘 · 버튼 "검색필터 · 10km 이내 · 편의시설 2개" | ✓ 정상 |
| 다시 열어 "초기화" 뒤 적용한다 | 거리 20km · 체크 해제 → 업체 검색(`radius_km` 20 · 필터 없이) · 항목은 다시 읽지 않는다 · 버튼 "검색필터 · 20km 이내" | ✓ 정상 |
| 거리 · 체크를 바꾸고 "닫기"를 누른다 | 검색하지 않는다 · 다시 열면 적용 중인 값 | — (지금 팝업과 같은 동작) |
| 항목을 못 읽었다 | 받은 문구 · 다시 열어 달라는 안내 · 거리만 골라 적용할 수 있다 | — (공통 실패 처리) |
| 결과가 300곳을 넘어 잘렸다 · 결과가 없다 | 검색필터에서 거리를 줄이거나 · 넓히거나 조건을 바꿔 보라는 안내 | — (문구만 바뀐다 — 지금 테스트의 기대 문구를 고친다) |

**계산 규칙 — 검색필터 버튼 글자**

검증: 거리를 정해 두면 "N km 이내", 체크한 것이 있으면 객실 · 편의시설을 모두 합쳐 "편의시설 N개"를 붙이고, 둘 다 없으면 "검색필터"만 보인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 거리만 정해 두면 거리만 붙는다 | 20km · 체크 없음 | `검색필터 · 20km 이내` |
| 거리 제한이 없으면 고른 수만 붙는다 | 제한 없음 · 3개 체크 | `검색필터 · 편의시설 3개` |
| 객실 항목도 편의시설 수에 합쳐 센다 | 20km · 객실 1개 · 편의시설 2개 체크 | `검색필터 · 20km 이내 · 편의시설 3개` |
| 거리 제한도 체크도 없으면 이름만 보인다 | 제한 없음 · 체크 없음 | `검색필터` |

**계산 규칙 — 필터 항목 묶음 나누기**

검증: 받은 항목을 받은 순서 그대로 객실 · 편의시설 묶음으로 나누고, 빈 묶음은 그리지 않으며, 모르는 묶음의 항목도 사라지지 않는다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 객실과 편의시설 항목이 함께 오면 두 묶음으로 나뉜다 | 객실 4개 다음 편의시설 7개 | "객실" 4개 · "편의시설" 7개, 받은 순서 그대로 |
| 한 묶음만 오면 그 묶음 하나만 보인다 | 객실 4개 | "객실" 묶음 하나 — 빈 "편의시설" 제목 없음 |
| 처음 보는 묶음의 항목은 맨 뒤 기타에 모인다 | 객실 1개 · 처음 보는 묶음 1개 | "객실" 1개 · 맨 뒤 "기타" 1개 |

## 2. 업체 상세 편의시설 — `PAGE /stores/[store_id]`

**동작 흐름**

1. **상세 읽기** — 들어오면 업체 상세를 읽는다(지금과 같다 — 응답에 `store_detail` 이 늘었다).
2. **이름 고르기** — 편의시설 중 값이 1인 것만 정한 순서의 이름으로 바꾼다(아래 계산 규칙).
3. **보이기** — 소개 아래 "편의시설" 칸에 글자 칩으로 보인다(객실 옵션 칩과 같은 모양).
   - 켜진 것이 없으면 → 칸을 통째로 숨긴다

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_id` | ✓ | 주소의 업체 ID(지금과 같다) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 편의점 · 주차만 있는 업체를 연다 | 소개 아래 "편의시설" 칸에 "편의점" · "주차" 칩 | ✓ 정상 |
| 편의시설이 하나도 없는 업체 | "편의시설" 칸이 없다 | — (계산 규칙 — 빈 목록이면 숨김) |

**계산 규칙 — 편의시설 이름 목록**

검증: 켜진 편의시설만 정한 순서(편의점 · 카페 · 온천 · 반려동물 동반 · 식사 제공 · 배달 음식 · 주차)의 이름으로 나오고, 하나도 없으면 빈 목록이다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 켜진 것만 정한 순서로 나온다 | 주차 · 편의점만 있음 | `편의점` · `주차` |
| 하나도 없으면 빈 목록이다 | 모두 없음 | 빈 목록(칸 숨김) |

## 3. 내 업체 설정 편의시설 탭 — `PAGE /manager/store`

**동작 흐름**

1. **탭 열기** — 내 업체 설정의 "편의시설" 탭(기본 정보 다음)을 누른다.
2. **처음 값** — 읽어 둔 내 업체의 `store_detail` 로 스위치 7개를 켜고 끈다.
3. **저장** — 스위치를 바꾸고 "저장"을 누르면 편의시설 설정(큐)에 7개를 모두 0 · 1 로 보낸다(통째로 교체 — 빠지면 꺼진다).
   - 서버가 거절하면 → 받은 문구(업체를 찾을 수 없음 등)
4. **다시 읽기** — 저장되면 내 업체를 다시 읽어 맞춘다(다른 탭과 같다).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `has_convenience_store` · `has_cafe` · `has_hot_spring` · `is_pet_allowed` · `has_meal` · `is_delivery_allowed` · `has_parking` | ✓ | 스위치 — 켜면 1, 끄면 0. 7개를 모두 보낸다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 편의점만 켜진 업체에서 온천을 켜고 저장한다 | 편의시설 설정(큐) 1번 — 7개 모두(편의점 1 · 온천 1 · 나머지 0) → 내 업체 다시 읽기 | ✓ 정상 |
| 값이 0 · 1 밖이다 | 생기지 않는다 | — (스위치라 0 · 1 만) |
| 서버가 거절한다 | 받은 문구 | — (공통 실패 처리) |
| 저장 뒤 내 업체를 못 읽었다 | 다시 불러오라는 안내 | — (다른 탭과 같은 공통 처리) |

## 데이터 변화

- 편의시설 저장(3)은 그 업체의 편의시설 7개를 통째로 바꾼다(백엔드 큐 — 보내지 않은 항목은 0). 소개 · 연락처 저장과는 따로다.
