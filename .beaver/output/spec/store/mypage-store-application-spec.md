# 마이페이지 · 입점 신청

## 한눈에

- **무엇을** 이용자가 마이페이지에서 내 정보 · 회원 상태를 보고 휴대폰 인증 · 로그아웃 · 탈퇴 신청 / 철회를 하고, 무인 객실 업체 입점을 신청한 뒤 사업자등록증 · 업체 사진을 올리고 결과(승인이면 업체 콘솔 로그인 주소)를 확인한다.
- **왜** 하단 탭 "마이"(`/me/`)와 회원 상태 띠의 "탈퇴 철회하기"가 가리키는 화면이 없고, 업체가 입점을 신청할 길이 없다.
- **범위 밖** 업체 콘솔 로그인 화면(Phase 10 — 여기서는 주소만 복사), 관리자 입점 심사(Phase 16), 신청 내용 고치기(API 없음 — 파일만 바꾼다).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 마이페이지 | 내 정보 · 회원 상태를 다시 읽어 보여 주고 탈퇴 신청 · 철회 · 로그아웃 | 6건 + 리뷰 고침 4건 |
| 2. 입점 신청 목록 | 내 신청 카드 — 반려 사유, 승인이면 업체코드 · 로그인 주소 | 6건 |
| 3. 입점 신청 작성 | 업체 정보 · 총관리자 계정을 받아 신청(큐)하고 상세로 | 5건(공백 다듬기는 정상 1건에) |
| 4. 입점 신청 상세 | 신청 내용 · 상태, 대기면 파일 올리기 · 지우기 · 신청 취소 | 3건 + 리뷰 고침 1건 |

## 1. 마이페이지 — `PAGE /me`

**동작 흐름**

1. 들어오면 내 정보를 다시 읽는다(앱을 연 뒤 회원 상태 · 휴대폰 인증이 바뀌었을 수 있다). 못 읽으면 이미 읽은 내 정보를 그대로 두고, 그것도 없으면 "다시 불러오기"를 보여 준다.
2. 닉네임 · 회원 상태 배지, 내 정보(가입한 SNS · 휴대폰과 인증 여부 · 성별 · 생년월일 · 가입일 · 회원 식별 코드), 메뉴(내 예약 · 입점 신청)를 보여 준다. 휴대폰 인증 전이면 "휴대폰 인증하기"로 인증 화면에 보낸다.
3. 이용 제한이면 사유 띠를, 탈퇴 대기면 탈퇴 예정 시각과 "탈퇴 철회"가 있는 띠를 보여 준다.
4. 탈퇴 신청은 사유(선택)를 받아 탈퇴(큐)하고, 탈퇴 철회는 철회(큐)한 뒤 둘 다 내 정보를 다시 읽는다. 다시 읽기가 실패하면 늦어짐이 아니라 "확인하지 못했어요"로 안내한다.
5. 로그아웃하면 이용자 토큰 쿠키를 지우고 첫 화면(지도) 문서를 새로 연다 — 로그인 상태는 바꾸지 않는다. 지우지 못하면 안내한다. 내 정보가 없어도 로그아웃은 보인다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `leave_comment` | | 탈퇴 사유(255자) — 탈퇴 신청 창에서 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 사유를 적고 탈퇴를 신청한다 | 탈퇴(큐) 1번(사유) → 내 정보 다시 읽음 → 탈퇴 대기 띠 | ✓ 정상 |
| 탈퇴 대기에서 철회한다 | 철회(큐) 1번 → 내 정보 다시 읽음 → 정상 | ✓ 정상 |
| 사유 없이 탈퇴를 신청한다 | 사유 없이 탈퇴(큐) | — (사유는 선택 — 공통 사유 입력 창) |
| 휴대폰 인증 전이다 | "인증 전" 배지 · "휴대폰 인증하기"(인증 뒤 이 화면으로) | — (그리기 · 링크만) |
| 이용 제한이다 | 정지 사유 띠 | — (공통 회원 상태 띠) |
| 로그아웃한다 | 토큰 쿠키 삭제 1번 → 첫 화면 문서를 새로 연다 | ✓ 정상 (리뷰 고침) |
| 토큰 쿠키를 지우지 못한다 | "로그아웃하지 못했어요" 팝업, 이동 없음 | ✓ 실패 (리뷰 고침) |
| 내 정보를 못 읽는다 | "다시 불러오기" · 로그아웃은 보이고 탈퇴 신청은 없다 | ✓ 실패 (리뷰 고침) |
| 탈퇴 · 철회 뒤 내 정보를 다시 읽지 못한다 | "확인하지 못했어요" 팝업(늦어짐과 나눈다) | ✓ 실패 (리뷰 고침) |
| 탈퇴 · 철회가 실패한다 · 늦어진다 | 사유 팝업 / 늦어짐 팝업 → 내 정보 다시 읽음 | — (큐 실패 공통 처리) |
| 로그인하지 않았다 | 로그인 화면 → 이 주소로 돌아옴 | — (공통 로그인 가드) |

**계산 규칙 — 전화번호 글자** `formatPhone`

검증: 숫자만 있는 전화번호를 휴대폰 · 서울 · 지역 · 대표번호 모양에 맞게 하이픈으로 나눈다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 휴대폰 11자리는 3 · 4 · 4로 나눈다 | `'01012345678'` | `'010-1234-5678'` |
| 서울 02 번호는 앞 두 자리를 지역번호로 둔다 | `'0212345678'` | `'02-1234-5678'` |
| 지역번호 3자리 10자리 번호는 3 · 3 · 4로 나눈다 | `'0311234567'` | `'031-123-4567'` |
| 8자리 대표번호는 4 · 4로 나눈다 | `'15771234'` | `'1577-1234'` |

## 2. 입점 신청 목록 — `PAGE /store-applications`

**동작 흐름**

1. 내 입점 신청을 한 쪽에 20개씩, 신청일 최신순으로 불러온다.
2. 위에 "새 입점 신청"을 두고, 카드마다 업체 이름 · 상태 배지 · 사업자등록번호 · 신청일을 보여 주며 누르면 상세로 간다.
3. 반려된 신청은 반려 사유를, 승인된 신청은 업체코드 · 업체 콘솔 로그인 주소 · "로그인 주소 복사"를 카드에 보여 준다.
4. 신청이 없으면 빈 안내를, 여러 쪽이면 페이지 탭을 보여 준다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| 쪽 | | 화면 상태(1부터) — 주소에 남기지 않는다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 대기 · 반려 · 승인 신청이 있다 | 1쪽 카드 — 상태 배지, 반려 사유, 승인이면 업체코드 · 로그인 주소 · 복사, 카드 링크는 상세 | ✓ 정상 |
| 신청이 없다 | "아직 보낸 입점 신청이 없어요" · 새 입점 신청 | — (공통 빈 안내) |
| 페이지 탭을 누른다 | 그 쪽을 다시 불러온다 | — (공통 페이지 탭) |
| 로그인하지 않았다 | 로그인 화면 → 이 주소로 돌아옴 | — (공통 로그인 가드) |

**계산 규칙 — 사업자등록번호 글자** `formatBusinessNumber`

검증: 10자리 숫자는 3 · 2 · 5로 나누고, 모양이 다르면 받은 그대로 보여 준다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 10자리 숫자는 3 · 2 · 5로 나눈다 | `'1234567890'` | `'123-45-67890'` |
| 10자리가 아니면 받은 그대로 보여 준다 | `'12345'` | `'12345'` |

**계산 규칙 — 업체 콘솔 로그인 주소** `managerLoginUrl`

검증: 프론트 주소와 하위 경로 뒤에 업체코드 로그인 주소를 붙이고, 끝은 `/`로 맞춘다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 프론트 주소 뒤에 업체코드 로그인 주소를 붙인다 | `('3f9a…c21', 'https://deskless.kr', '')` | `'https://deskless.kr/manager/3f9a…c21/login/'` |
| 하위 경로로 배포하면 그 경로를 사이에 넣는다 | `('3f9a…c21', 'https://deskless.kr', '/app')` | `'https://deskless.kr/app/manager/3f9a…c21/login/'` |
| 프론트 주소 끝에 `/`가 있어도 겹치지 않는다 | `('3f9a…c21', 'https://deskless.kr/', '')` | `'https://deskless.kr/manager/3f9a…c21/login/'` |

## 3. 입점 신청 작성 — `PAGE /store-applications/new`

**동작 흐름**

1. 업체 정보(상호명 · 사업자등록번호 · 업체 연락처 · 주소 · 상세 주소), 대표자 · 업체 총관리자 계정(대표자명 · 대표자 휴대폰 · 아이디 · 비밀번호), 남길 말(선택)을 받는다. 번호 칸은 숫자만 남긴다.
2. 주소는 "주소 검색"으로만 고르고, 고른 주소의 위도 · 경도를 함께 저장한다.
3. "신청하기"를 누르면 입력을 검사해 틀린 칸 옆에 오류를 보여 주고, 맞으면 입점 신청(큐)을 보낸다. 상호명 · 대표자명 · 총관리자 아이디는 앞뒤 공백을 다듬어 검사한다(공백뿐이면 비어 있음).
4. 신청이 되면 상세로 가서 사업자등록증을 올리게 한다. 늦어지면 안내 뒤 목록으로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_name` | ✓ | 상호명(100자) |
| `business_number` | ✓ | 사업자등록번호 숫자 10자리 |
| `phone` | ✓ | 업체 연락처 숫자 8~11자리 |
| `address` · `latitude` · `longitude` | ✓ | 주소 검색으로 고른 주소와 좌표 |
| `address_detail` | | 상세 주소(255자) |
| `owner_name` · `owner_phone` | ✓ | 대표자명(50자) · 대표자 휴대폰(숫자만) — 승인 때 업체 총관리자 계정 |
| `head_manager_login_id` · `head_manager_login_pw` | ✓ | 업체 콘솔 아이디(영문 · 숫자 · _ 4~30자) · 비밀번호(8~20자, 영문 + 숫자) |
| `application_comment` | | 관리자에게 남길 말(500자) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 모든 칸을 맞게 채우고 신청한다 | 입점 신청(큐) 1번(주소 검색 좌표 포함) → 상세로 | ✓ 정상 |
| 사업자등록번호가 10자리가 아니다 | 칸 옆 "사업자등록번호 10자리를 숫자만 입력해주세요.", 신청 0번 | ✓ 검증 실패 |
| 주소 검색을 하지 않았다 | 주소 칸 옆 오류, 신청 0번 | — (같은 DTO 검증) |
| 신청이 실패한다 | 칸 옆 오류(`validation_errors`) 또는 사유 팝업 | — (공통 실패 처리) |
| 신청이 늦어진다 | 늦어짐 팝업 → 목록 | — (큐 늦어짐 공통) |

**계산 규칙 — 입력 칸 숫자만 남기기** `digitsOnly`

검증: 붙여 넣은 번호에서 숫자만 남기고, 칸의 자릿수를 넘으면 자른다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 하이픈 · 공백을 넣어 붙여 넣어도 숫자만 남긴다 | `('010-1234 5678', 11)` | `'01012345678'` |
| 자릿수를 넘으면 앞에서부터 자른다 | `('123456789012', 10)` | `'1234567890'` |
| 숫자가 없으면 빈 글자다 | `('abc', 10)` | `''` |

## 4. 입점 신청 상세 — `PAGE /store-applications/[store_application_id]`

**동작 흐름**

1. 내 신청 상세를 불러온다. 없거나 남의 신청이면 안내 뒤 목록으로 보낸다.
2. 업체 이름 · 상태 배지 · 신청일(처리일)과 상태 띠를 보여 준다 — 대기면 사업자등록증이 없을 때 "아직 없어요", 반려면 반려 사유, 승인이면 업체코드 · 업체 콘솔 로그인 주소 · "로그인 주소 복사".
3. 대기면 사업자등록증(1장) · 업체 사진(5장까지)을 올리고 지울 수 있다. 올리기는 업로드 주소 발급 → 파일 PUT → 등록(큐), 지우기는 확인 뒤 삭제(큐), 끝나면 상세를 다시 불러온다. 대기가 아니면 파일은 보기만 한다.
4. 대기면 "신청 취소"로 확인 뒤 취소(큐)한다. 결과가 null(done · pending 같음)이라 상세를 다시 읽어 없어졌으면(404) 목록으로 가고, 남아 있으면 늦어짐 안내 뒤 상세를 다시 불러온다.
5. 신청 내용(상호명 · 사업자등록번호 · 대표자 · 대표자 휴대폰 · 총관리자 아이디 · 업체 연락처 · 주소 · 남길 말)을 보여 준다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_application_id` | ✓ | 주소의 신청 |
| 파일 | | 사업자등록증 · 업체 사진(JPG · PNG) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 대기 신청에 사업자등록증을 올린다 | 업로드 주소 발급(용도 사업자등록증) → PUT → 등록(큐) → 상세 다시 | ✓ 정상 |
| 대기 신청을 취소한다 | 확인 뒤 취소(큐) 1번 → 상세 다시 읽어 없음(404) → 목록 | ✓ 정상 |
| 취소(큐) 뒤에도 신청이 남아 있다 | 늦어짐 팝업 → 목록으로 가지 않고 상세 다시 | ✓ 실패 (리뷰 고침) |
| 승인된 신청을 연다 | 업체코드 · 로그인 주소 · 복사, 파일은 보기만, 신청 취소 없음 | ✓ 정상 |
| 사진을 지운다 | 확인 뒤 삭제(큐) → 상세 다시 | — (취소와 같은 흐름) |
| JPG · PNG 가 아닌 파일을 고른다 | "JPG · PNG 사진만 올릴 수 있습니다." | — (공통 올리기 검사) |
| 사업자등록증이 이미 1장 · 업체 사진이 5장이다 | 올리기 칸을 숨긴다 | — (그리기만) |
| 반려된 신청을 연다 | 반려 사유, 파일은 보기만, 신청 취소 없음 | — (승인과 같은 보기 전용) |
| 없거나 남의 신청이다 | "입점 신청을 찾을 수 없습니다." → 목록 | — (예약 1건과 같은 처리) |

## 결정한 것

- [x] 테스트는 전화번호 · 사업자번호 글자, 입력 칸 숫자만 남기기, 업체 콘솔 로그인 주소를 계산 규칙으로 쓴다(사용자 결정 2026-11-18).
- [x] 입점 신청 파일 칸은 시안대로 이 화면 전용 부품(사업자등록증 칸 + 업체 사진 3열 격자)으로 만들고, 올리기는 공통 `uploadFile` 을 쓴다. 근거: 신청 파일에는 대표 · 순서가 없어 공통 사진 부품의 대표 배지 · 손잡이가 맞지 않는다(사용자 결정 2026-11-18).
- [x] 내 정보에 회원 식별 코드를 넣는다. 근거: 지침서 U10 구성에 있고(고객 문의 때 알려 주는 코드), 시안에는 없지만 지침서가 기준이다.
- [x] 탈퇴 대기 띠의 "탈퇴 철회"는 띠 안 버튼이다. 근거: 시안 U10(탈퇴 대기) — 공통 회원 상태 띠가 다른 화면에서는 이 화면으로 가는 링크를, 이 화면에서는 철회 버튼을 받도록 넓힌다.
- [x] 로그아웃은 토큰 쿠키를 지운 뒤 첫 화면을 새로 연다 — 로그인 상태는 바꾸지 않는다(`auth.logout()` 은 쿠키만 지우고 성공 여부를 돌려준다 → `replaceDocument('/')`). 근거: 로그인 상태를 바꾸거나 화면 안에서 이동하면 로그인 가드가 먼저 로그인 화면으로 보내고, 새로 열어야 내 정보 같은 이용자 상태가 남지 않는다(리뷰 261118-3 #2).
- [x] 업체 콘솔 로그인 주소는 프론트 주소(`NEXT_PUBLIC_SERVER_URL`) + 하위 경로 + `/manager/<업체코드>/login/`. 근거: 지침서 U11("<프론트 주소>/manager/<store_code>/login"), 링크는 `/` 로 끝난다(`trailingSlash`), 화면이 그려지기 전 서버에서도 같은 값이다.
- [x] 신청이 늦어지면(큐 결과 없음) 신청 ID 를 몰라 목록으로 간다. 근거: 큐 늦어짐은 그 리소스를 다시 조회한다(AGENTS.md "Data Layer").
- [x] 신청 내용은 고치지 않는다. 근거: 수정 API 가 없다 — 대기 신청은 파일만 바꾸고, 다시 쓰려면 취소 뒤 새로 신청한다.
