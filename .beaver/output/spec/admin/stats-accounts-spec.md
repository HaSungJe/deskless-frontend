# 통계 · 계정 · 이용자 — 대시보드와 회원 관리

## 한눈에

- **무엇을** 관리자가 전체 업체의 이용 · 결제 통계를 기간별로 보고, 모든 업체의 업체 관리자 계정을 찾아 비밀번호를 초기화하고, 이용자를 찾아 이용을 제한하거나 풀어 준다.
- **왜** 관리자 첫 화면이 아직 "준비 중"이고, 업체 관리자가 비밀번호를 잃거나 이용자가 문제를 일으켜도 관리자가 손쓸 화면이 없다. 업체 상세 · 입점 신청 상세의 "이 업체의 업체 관리자" · "이용자 상세" 링크도 이 화면들을 기다린다.
- **범위 밖** 업체 관리자 계정의 정보 수정 · 정지 · 삭제(그 업체의 업체 총관리자가 업체 관리자 콘솔에서 — 여기서는 보기와 비밀번호 초기화만), 이용자 정보 수정 · 예약 취소(관리자 API 가 없다).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 대시보드 | 기간 · 결제 환경 · 업체 범위 → 합계 · 월별 · 업체별 통계 | 2건 |
| 2. 업체 관리자 목록 | 업체 · 권한 · 상태 · 검색 · 표 | 2건 |
| 3. 업체 관리자 상세 | 계정 정보 · 비밀번호 초기화 | 4건 |
| 4. 이용자 목록 | 상태 · SNS · 검색 · 표 | 1건 |
| 5. 이용자 상세 | 회원 정보 · 이용 제한 · 해제 · 예약 요약 · 이력 | 5건 |

## 1. 대시보드 — `PAGE /admin`

**동작 흐름**

1. **통계 읽기** — 들어오면 기간을 비운 채(최근 3개월) 실결제 · 활동 업체만 · 1쪽으로 전체 통계를 읽고, 받은 기간을 달 칸에 채운다.
2. **조건 고르기** — 시작 달 · 끝 달 · 결제 환경(실결제 · 테스트 결제) · 업체 범위(활동 업체만 · 모든 업체)를 고른다. 고르는 동안은 다시 읽지 않는다.
3. **조회** — "조회"를 누르면 고른 조건 · 1쪽으로 다시 읽는다.
   - 기간이 12개월을 넘거나 시작이 끝보다 늦으면 → 서버 문구를 달 칸 옆에
4. **결과 보이기** — 합계 카드 5개, 월별 결제액 · 환불액 막대그래프, 월별 표(달마다 한 줄 + 합계 줄), 업체별 표(수익 많은 순)를 보인다.
5. **쪽 넘기기** — 업체별 표 아래 페이지 번호로 같은 조건의 다른 쪽을 읽는다.
6. **업체로 이동** — 업체별 표의 상호명을 누르면 그 업체 상세로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `start_month` · `end_month` | | 시작 달 · 끝 달(`YYYY-MM`) — 비우면 보내지 않는다(최근 3개월), 최대 12개월 |
| `environment` | ✓ | 결제 환경 — 실결제 `LIVE`(처음) · 테스트 결제 `TEST` |
| `has_activity` | ✓ | 업체 범위 — 활동 업체만 `1`(처음) · 모든 업체 `0`. 업체별 표에만 쓰인다 |
| `page` | ✓ | 업체별 표 쪽(처음 1) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 처음 들어온 뒤 기간 · 테스트 결제 · 모든 업체를 골라 조회한다 | 처음 통계 1번(기간 없음 · 실결제 · 활동 업체만 · 1쪽) → 받은 기간이 달 칸에 → 조회 1번(고른 기간 · `TEST` · `0` · 1쪽). 합계 카드 5개(이용자 수 명 · 이용 건수 건 · 결제액 · 환불액 · 수익 원), 월별 표(달 줄 + 합계 줄), 업체별 표(상호명 → 업체 상세 · 업체코드 · 상태 · 값 5개) | ✓ 정상 |
| 업체별 표를 2쪽으로 넘긴다 | 마지막으로 조회한 조건 그대로 · 2쪽으로 다시(칸만 고치고 조회하지 않은 값은 쓰지 않는다) | ✓ 정상 |
| 수익이 음수인 달 · 업체가 있다 | 그 값을 위험색으로(`-320,000`) | — (보여 주기만) |
| 기간 안에 활동한 업체가 없다 | 업체별 표 자리에 "기간 안에 활동한 업체가 없습니다." | — (공통 빈 안내) |
| 서버가 기간을 거절한다(12개월 넘김 · 시작이 끝보다 늦음) | 받은 문구를 시작 달 · 끝 달 칸 옆에 | — (공통 실패 처리 — 칸 오류는 칸 옆) |
| 통계를 못 읽었다 | 받은 문구 | — (공통 실패 처리) |

## 2. 업체 관리자 목록 — `PAGE /admin/managers`

**동작 흐름**

1. **목록 읽기** — 들어오면 업체 고르기 칸을 채울 업체 전부와, 모든 업체의 업체 관리자 1쪽(등록 최신순)을 읽는다.
   - 업체 상세의 "이 업체의 업체 관리자"로 왔으면 → 그 업체가 골라진 채 1쪽
2. **거르기** — 업체를 고르거나, 권한 칩(전체 · 총괄매니저 · 매니저) · 상태 칩(전체 · 정상 · 정지)을 누르거나, 검색어(상호명 · 업체코드 · 아이디 · 이름 · 휴대폰)로 조회하면 1쪽부터 다시 읽는다.
3. **쪽 넘기기** — 아래 페이지 번호로 다른 쪽을 읽는다.
4. **상세로 이동** — 이름을 누르면 업체 관리자 상세로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_id` | | 고른 업체 — "전체 업체"면 보내지 않는다. 주소 `?store_id=` 로 처음 값이 올 수 있다 |
| `auth_id` | | 권한 칩 — 총괄매니저 `HEAD_MANAGER` · 매니저 `MANAGER`, 전체면 보내지 않는다 |
| `state_id` | | 상태 칩 — 정상 `ACTIVE` · 정지 `BLOCK`, 전체면 보내지 않는다 |
| `keyword` | | 검색어(100자까지) |
| `page` | ✓ | 보는 쪽(처음 1) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 · 총괄매니저 · 정지를 고르고 검색어로 조회한다 | 업체 고르기용 업체 목록 1번(전부) · 목록 다시(그 업체 · `HEAD_MANAGER` · `BLOCK` · 검색어 · 1쪽) — 표: 업체(활성이 아니면 상태 배지) · 업체코드(앞 8자) · 아이디 · 이름(상세 링크) · 휴대폰 · 권한 · 상태(임시 비밀번호면 "임시 비밀번호" 배지) · 등록일시 | ✓ 정상 |
| 업체 상세에서 "이 업체의 업체 관리자"로 들어온다 | 업체 칸에 그 업체가 골라져 있고, 첫 목록부터 그 업체 · 1쪽으로 읽는다 | ✓ 정상 |
| 휴대폰이 없는 계정 | 휴대폰 칸 "—" | — (보여 주기만) |
| 조건에 맞는 계정이 없다 | "조건에 맞는 업체 관리자가 없습니다." · 거르기를 풀거나 검색어를 지워 보라는 안내 | — (공통 빈 안내) |
| 목록을 못 읽었다 | 받은 문구 | — (공통 실패 처리) |

## 3. 업체 관리자 상세 — `PAGE /admin/managers/[user_id]`

**동작 흐름**

1. **상세 읽기** — 들어오면 계정 정보(업체 · 업체코드 · 아이디 · 이름 · 휴대폰 · 성별 · 생년월일 · 권한 · 상태 · 정지 사유 · 비밀번호 변경 필요 · 등록일시)를 읽는다.
   - 없는 계정이면 → 받은 문구와 목록으로 가는 링크만
2. **초기화 판단** — 휴대폰이 없거나 탈퇴한 업체의 계정이면 "비밀번호 초기화"를 끄고 이유를 보인다(정지 계정은 초기화할 수 있다).
3. **확인** — "비밀번호 초기화"를 누르면 확인 창에 누구의 비밀번호를 어느 휴대폰으로 보내는지 보인다.
   - 취소하면 → 부르지 않는다
4. **초기화** — 확인하면 비밀번호 초기화(큐)를 부르고, "임시 비밀번호를 <휴대폰> 로 보냈습니다." 띠를 보인 뒤 상세를 다시 읽는다(비밀번호 변경 필요 → 예).
   - 서버가 거절하면 → 받은 문구

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `user_id` | ✓ | 주소의 업체 관리자 회원 ID |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 초기화를 누르고 확인한다 | 확인 창 "이서연(gn_front01)의 임시 비밀번호를 만들어 010-4567-8901 로 SMS 를 보냅니다. …" → 초기화(큐) 1번(그 계정) → "임시 비밀번호를 010-4567-8901 로 보냈습니다." 띠 → 상세 다시(상세 2번) | ✓ 정상 |
| 확인 창에서 취소한다 | 창 닫힘 · 초기화 0번 | — (공통 확인 창) |
| 업체 이름을 누른다 · 업체코드를 복사한다 | 업체 상세로 · 업체코드 전체가 복사된다 | — (링크 · 공통 복사 버튼) |
| 서버가 거절한다(그 사이 휴대폰이 지워짐 등) | 받은 문구 | — (공통 실패 처리) |
| 없는 계정 | 받은 문구 · 목록 링크 | — (공통 실패 처리) |

**계산 규칙 — 비밀번호를 초기화할 수 있는지**

검증: 휴대폰이 있고 탈퇴한 업체가 아닌 계정만 초기화 버튼이 켜지고, 막힐 때는 이유를 보인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 정지된 계정이라도 휴대폰이 있으면 초기화할 수 있다 | 정지 계정 · 휴대폰 있음 · 업체 활성 | 버튼 켜짐 · 막는 이유 없음 |
| 휴대폰이 없으면 막고 이유를 보인다 | 정상 계정 · 휴대폰 없음 · 업체 활성 | 버튼 꺼짐 · "휴대폰 번호가 등록되지 않은 계정입니다. 그 업체의 업체 총관리자가 휴대폰 번호를 넣은 뒤 초기화할 수 있습니다." |
| 탈퇴한 업체의 계정이면 막고 이유를 보인다 | 정지 계정 · 휴대폰 있음 · 업체 탈퇴 | 버튼 꺼짐 · "탈퇴한 업체의 계정이라 초기화할 수 없습니다." |

## 4. 이용자 목록 — `PAGE /admin/users`

**동작 흐름**

1. **목록 읽기** — 들어오면 모든 이용자 1쪽을 가입 최신순으로 읽는다.
2. **거르기** — 상태 칩(전체 · 정상 · 정지 · 탈퇴 대기 · 탈퇴)을 누르거나, SNS(전체 · 카카오 · 네이버 · 구글 · 애플 · 페이스북 · 라인)를 고르거나, 검색어(이름 · 닉네임 · 휴대폰 · 검색 코드)로 조회하면 1쪽부터 다시 읽는다.
3. **쪽 넘기기** — 아래 페이지 번호로 다른 쪽을 읽는다.
4. **상세로 이동** — 닉네임을 누르면 이용자 상세로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `state_id` | | 상태 칩 — 정상 `ACTIVE` · 정지 `BLOCK` · 탈퇴 대기 `LEAVE_WAIT` · 탈퇴 `LEAVE`, 전체면 보내지 않는다 |
| `sns_id` | | SNS — `KAKAO` · `NAVER` · `GOOGLE` · `APPLE` · `FACEBOOK` · `LINE`, 전체면 보내지 않는다 |
| `keyword` | | 검색어(100자까지) |
| `page` | ✓ | 보는 쪽(처음 1) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 정지 · 카카오를 고르고 검색어로 조회한다 | 목록 다시(`BLOCK` · `KAKAO` · 검색어 · 1쪽) — 표: 검색 코드(앞 8자) · 닉네임(상세 링크) · 이름 · 휴대폰 · SNS · 상태 · 가입일시. 휴대폰이 없고 미인증이면 "미인증" 배지, 탈퇴면 "—" | ✓ 정상 |
| 조건에 맞는 이용자가 없다 | "조건에 맞는 이용자가 없습니다." · 거르기를 풀거나 검색어를 지워 보라는 안내 | — (공통 빈 안내) |
| 목록을 못 읽었다 | 받은 문구 | — (공통 실패 처리) |

## 5. 이용자 상세 — `PAGE /admin/users/[user_id]`

**동작 흐름**

1. **상세 읽기** — 들어오면 회원 정보 · 예약 요약(전체 · 진행 중 · 이용 완료 · 취소)과 예약 이력 1쪽(이용 시작 최신순)을 읽는다.
   - 없는 이용자면 → 받은 문구와 목록으로 가는 링크만
2. **상태별 칸** — 정상이면 이용 제한 칸(사유 선택 · 255자), 정지면 제한 사유와 "제한 해제", 탈퇴 대기 · 탈퇴면 "바꿀 수 없습니다" 띠와 꺼진 버튼을 보인다.
3. **이용 제한** — "이용 제한"을 누르면 확인 창 뒤에 상태 변경(큐 — 정지 · 사유)을 부르고, "이용을 제한했습니다. …" 띠를 보인 뒤 상세를 다시 읽는다.
   - 취소하면 → 부르지 않는다
4. **제한 해제** — "제한 해제"를 누르면 확인 없이 상태 변경(큐 — 정상)을 부르고 상세를 다시 읽는다(사유는 지워진다).
   - 그 사이 상태가 바뀌었으면 → 서버 문구 "회원 상태가 바뀌었습니다. 다시 확인해주세요."
5. **이력 쪽 넘기기** — 예약 이력 아래 페이지 번호로 다른 쪽을 읽는다.
6. **업체로 이동** — 예약 이력의 업체 이름을 누르면 그 업체 상세로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `user_id` | ✓ | 주소의 이용자 회원 ID |
| `state_id` | 바꿀 때 ✓ | 이용 제한 `BLOCK` · 해제 `ACTIVE` |
| `block_comment` | | 이용 제한 사유(255자까지, 비우면 보내지 않는다) — 이용자 화면에 보인다 |
| `page` | ✓ | 예약 이력 쪽(처음 1) |

**결과**

| 상황 | 응답 | 테스트 |

## 데이터 변화

- 업체 관리자 비밀번호 초기화(3)는 그 계정의 비밀번호를 임시 비밀번호로 바꾸고 "비밀번호 변경 필요"로 둔 뒤, 그 계정 휴대폰으로 임시 비밀번호 문자를 보낸다(백엔드). 지금 비밀번호로는 더 이상 로그인할 수 없다.
- 이용자 상태 변경(5)은 이용자를 정지(이용 제한 사유와 함께)나 정상으로 바꾼다(백엔드 큐). 정지된 이용자는 로그인 · 이미 한 예약의 이용은 되고 새 예약 · 연장만 막힌다. 해제하면 사유가 지워진다.
- 대시보드 · 두 목록은 읽기만 한다. 화면이 따로 저장하는 값은 없다.

## 제안 (코드베이스 기반)

- 관리자 목록 거르기(`src/app/admin/(console)/_components/ListFilter.tsx`)는 상태 칩 하나 · 검색어만 받는다 — 업체 고르기 · 권한 칩 · SNS 고르기를 끼울 자리를 더해 세 목록이 함께 쓴다(plan 에서).
