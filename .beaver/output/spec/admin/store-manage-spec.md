# 입점 신청 · 업체 관리 — 승인 · 반려 · 업체 상태

## 한눈에

- **무엇을** 관리자가 이용자가 보낸 입점 신청을 보고 승인(업체 · 업체 총관리자 계정이 생긴다) 또는 반려하고, 만들어진 업체의 정보 · 상태(활성 · 영업중지 · 탈퇴) · 영업중 여부를 관리한다.
- **왜** 입점 신청(U11)이 와도 승인할 화면이 없어 업체가 생기지 않고, 생긴 업체를 멈추거나 고칠 길이 없다.
- **범위 밖** 업체의 사진 · 영업시간 · 운영 규정 바꾸기(업체 관리자가 내 업체 설정에서 — 여기서는 보기만), 업체 관리자 목록(A5) · 이용자 상세(A6)는 Phase 17 — 그 전에는 이 화면의 링크를 눌러도 없는 화면.

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 입점 신청 목록 | 상태 칩 · 검색 · 표 | 1건 |
| 2. 입점 신청 상세 | 신청 내용 · 신청자 · 파일 · 승인 · 반려 | 7건 |
| 3. 업체 목록 | 상태 칩 · 검색 · 표 | 1건 |
| 4. 업체 상세 | 정보 수정(주소 검색) · 상태 · 영업중 · 파일 | 5건 |

## 1. 입점 신청 목록 — `PAGE /admin/store-applications`

**동작 흐름**

1. **목록 읽기** — 들어오면 모든 상태의 신청 1쪽을 신청일 최신순으로 읽는다.
2. **거르기** — 상태 칩(전체 · 대기 · 승인 · 반려)을 고르거나 검색어(상호명 · 사업자등록번호)로 조회하면 1쪽부터 다시 읽는다.
3. **쪽 넘기기** — 아래 페이지 번호로 다른 쪽을 읽는다.
4. **상세로 이동** — 상호명을 누르면 신청 상세로, 승인된 신청의 "업체 보기"를 누르면 그 업체 상세로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_application_state_id` | | 상태 칩 — 대기 `WAIT` · 승인 `APPROVED` · 반려 `REJECTED`, 전체면 보내지 않는다 |
| `keyword` | | 검색어(100자까지) — 상호명 · 사업자등록번호 |
| `page` | ✓ | 보는 쪽(처음 1) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| "대기"를 고르고 검색어로 조회한다 | 목록 다시(대기 · 검색어 · 1쪽) — 표: 번호 · 상호명 · 사업자등록번호 · 대표자 · 상태 · 신청 일시 · 처리 일시 · 만든 업체 | ✓ 정상 |
| 조건에 맞는 신청이 없다 | "조건에 맞는 입점 신청이 없습니다." · 상태를 전체로 바꾸거나 검색어를 지워 보라는 안내 | — (공통 빈 안내) |
| 목록을 못 읽었다 | 받은 문구 | — (공통 실패 처리) |

## 2. 입점 신청 상세 — `PAGE /admin/store-applications/[store_application_id]`

**동작 흐름**

1. **상세 읽기** — 들어오면 신청 내용 · 신청자 · 처리 결과 · 업체 정보 파일을 읽는다. 사업자등록증 열람 주소는 10분만 열려 상세를 열 때마다 새로 받는다.
   - 없는 신청이면 → 받은 문구와 목록으로 가는 링크만
2. **승인 가능 판단** — 대기 중인 신청만 반려 · 승인 버튼을 보이고, 사업자등록증이나 신청자 정보가 없으면 승인을 막고 이유를 띠로 보인다.
3. **승인** — "승인"을 누르면 입점 승인(큐)을 부른다. 업체와 업체 총관리자 계정(신청 때 정한 아이디 · 비밀번호)이 만들어지고 대표자 휴대폰으로 승인 문자가 간다.
   - 서버가 거절하면 → 받은 문구
4. **승인 결과 안내** — 상세를 다시 읽고, 받은 업체코드와 업체 콘솔 로그인 주소(복사 · 업체 상세로)를 띠로 보인다.
5. **반려** — "반려"를 누르면 사유 대화상자가 열리고, 사유(필수 · 255자)를 넣어 입점 반려(큐)를 부른 뒤 닫고 상세를 다시 읽는다.
   - 사유가 비면 → "반려하기"가 꺼져 부르지 않는다

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_application_id` | ✓ | 주소의 입점 신청 ID |
| `reject_comment` | 반려 때 ✓ | 반려 사유(255자까지) — 신청자가 내 신청 화면에서 본다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 대기 신청을 승인한다 | 승인(큐) 1번(그 신청) → 상세 다시 → "입점을 승인했습니다. 대표자 휴대폰으로 승인 문자를 보냈습니다." 띠 · 업체코드 · 로그인 주소(복사) · 업체 상세 링크 | ✓ 정상 |
| 사유를 넣어 반려한다 | 반려(큐) 1번(그 신청 · 앞뒤 빈칸을 뗀 사유) → 대화상자 닫힘 → 상세 다시 | ✓ 정상 |
| 사유를 비우고 반려하려 한다 | "반려하기" 버튼이 꺼져 있다, 반려 0번(서버가 사유를 거절하면 칸 옆에) | ✓ 검증 실패 |
| 승인 결과가 늦어 결과 없이 끝난다 | 상세를 다시 읽고, 다시 읽은 업체코드로 같은 띠(아직 없으면 띠 없이 상태만) | — (큐 공통 — 결과가 없으면 다시 조회) |
| 서버가 거절한다(이미 처리됨 · 사업자등록증 없음 등) | 받은 문구 | — (공통 실패 처리) |
| 없는 신청 | 받은 문구 · 목록 링크 | — (공통 실패 처리) |
| 사업자등록증을 연다 | 새 창으로 열람 주소(10분 — 지나면 새로고침 안내) | — (링크만) |
| 신청자가 없다 | 신청자 칸에 "신청자 정보 없음" | — (아래 계산 규칙이 승인을 막는다) |

**계산 규칙 — 승인할 수 있는지** `approvalOf`

검증: 대기 중인 신청만 반려 · 승인 버튼이 보이고, 사업자등록증과 신청자가 모두 있어야 승인이 켜진다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 대기 중이고 사업자등록증 · 신청자가 있으면 승인할 수 있다 | 대기 · 사업자등록증 1장 · 신청자 있음 | 버튼 보임 · 승인 켜짐 · 막는 이유 없음 |
| 사업자등록증이 없으면 승인을 막고 이유를 보인다 | 대기 · 업체 사진만 · 신청자 있음 | 승인 꺼짐 · "사업자등록증이 없어 승인할 수 없습니다. 신청자가 내 신청 화면에서 사업자등록증을 올린 뒤 승인하세요." |
| 신청자 정보가 없으면 승인을 막고 이유를 보인다 | 대기 · 사업자등록증 1장 · 신청자 없음 | 승인 꺼짐 · "신청자 정보를 찾을 수 없어 승인할 수 없습니다." |
| 이미 처리된 신청이면 버튼을 숨긴다 | 반려됨 | 반려 · 승인 버튼 없음 |

## 3. 업체 목록 — `PAGE /admin/stores`

**동작 흐름**

1. **목록 읽기** — 들어오면 모든 상태의 업체 1쪽을 등록일 최신순으로 읽는다.
2. **거르기** — 상태 칩(전체 · 활성 · 영업중지 · 탈퇴)을 고르거나 검색어(상호명 · 사업자등록번호 · 대표자명)로 조회하면 1쪽부터 다시 읽는다.
3. **쪽 넘기기** — 아래 페이지 번호로 다른 쪽을 읽는다.
4. **상세로 이동** — 상호명을 누르면 업체 상세로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_state_id` | | 상태 칩 — 활성 `ACTIVE` · 영업중지 `SUSPEND` · 탈퇴 `LEAVE`, 전체면 보내지 않는다 |
| `keyword` | | 검색어(100자까지) — 상호명 · 사업자등록번호 · 대표자명 |
| `page` | ✓ | 보는 쪽(처음 1) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| "영업중지"를 고르고 검색어로 조회한다 | 목록 다시(영업중지 · 검색어 · 1쪽) — 표: 업체코드(앞 8자) · 상호명 · 사업자등록번호 · 대표자 · 전화 · 주소 · 영업중 · 상태 | ✓ 정상 |
| 탈퇴 업체가 있다 | 사업자등록번호 자리에 `DELETE_…` 를 줄여 흐리게 | — (보여 주기만) |
| 조건에 맞는 업체가 없다 | "조건에 맞는 업체가 없습니다." · 상태를 전체로 바꾸거나 검색어를 지워 보라는 안내 | — (공통 빈 안내) |
| 목록을 못 읽었다 | 받은 문구 | — (공통 실패 처리) |

## 4. 업체 상세 — `PAGE /admin/stores/[store_id]`

**동작 흐름**

1. **상세 읽기** — 들어오면 업체 정보 · 상태 · 영업중 · 운영 규정 · 파일을 읽어 칸을 채운다.
   - 탈퇴한 업체면 → 모든 칸 · 버튼을 잠그고 안내 띠
2. **주소 검색** — "주소 검색"으로 주소를 고르면 주소와 위도 · 경도 칸이 채워진다(칸은 직접 고칠 수도 있다).
3. **정보 저장** — 상호명 · 대표자 · 연락처(숫자만) · 주소 · 상세주소 · 위도 · 경도를 검사해 업체 정보 수정(큐)을 부르고 상세를 다시 읽는다.
   - 틀린 칸이 있으면 → 칸 옆 오류, 부르지 않는다
4. **상태 변경** — 지금과 다른 상태를 고르면 "상태 변경"이 켜지고, 영업중지는 사유(선택 · 255자)를 넣어 업체 상태 변경(큐)을 부른 뒤 상세를 다시 읽는다.
   - 탈퇴를 고르면 → 확인 대화상자(되돌릴 수 없음 · 업체 관리자 계정 모두 정지) 뒤에 부른다
5. **영업중 바꾸기** — 영업중 스위치를 누르면 바로 영업중 여부 변경(큐)을 부르고 상세를 다시 읽는다.
6. **업체 관리자로** — "이 업체의 업체 관리자"를 누르면 그 업체로 거른 업체 관리자 목록(A5 — Phase 17)으로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_id` | ✓ | 주소의 업체 ID |
| `store_name` · `owner_name` | ✓ | 상호명(100자) · 대표자명(50자) |
| `phone` | ✓ | 업체 연락처 — 숫자만 8 ~ 11자리(칸에 숫자만 들어간다) |
| `address` · `address_detail` | 주소 ✓ | 주소(255자) · 상세주소(255자, 비우면 지운다) |
| `latitude` · `longitude` | ✓ | 위도 · 경도 — 주소 검색이 채운다 |
| `store_state_id` · `suspend_comment` | 상태 변경 때 ✓ | 바꿀 상태 · 정지 사유(영업중지일 때만, 255자) |
| `is_open` | 영업중 때 ✓ | 영업중 1 · 영업준비 0 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 주소를 검색해 고치고 저장한다 | 정보 수정(큐) 1번(상호명 · 대표자 · 숫자만 연락처 · 고른 주소 · 숫자 위도 · 경도 · 상세주소) → 상세 다시 | ✓ 정상 |
| 연락처를 7자리만 넣고 저장한다 | 칸 옆 "업체 연락처를 숫자만 정확히 입력해주세요.", 수정 0번(연락처 칸은 숫자만 들어간다) | ✓ 검증 실패 |
| 영업중지를 고르고 사유를 넣어 바꾼다 | 상태 변경(큐) 1번(영업중지 · 앞뒤 빈칸을 뗀 사유) → 상세 다시 | ✓ 정상 |
| 탈퇴를 고르고 확인한다 | 확인 대화상자 → 상태 변경(큐) 1번(탈퇴 · 사유 없음) → 상세 다시 | ✓ 정상 |
| 영업중 스위치를 끈다 | 영업중 변경(큐) 1번(영업준비 0) → 상세 다시 | ✓ 정상 |
| 지금과 같은 상태를 고른다 | "상태 변경" 꺼짐 | — (지금 상태와 비교 하나 — 서버도 400 "이미 같은 상태입니다.") |
| 영업중지 업체다 | 머리 아래 "영업중지 사유 · …" 띠(사유가 없으면 띠 없음) | — (보여 주기만) |
| 탈퇴한 업체다 | "탈퇴한 업체는 바꿀 수 없습니다." 띠 · 정보 · 상태 · 영업중 칸 모두 잠김 | — (보여 주기만 — 서버도 막는다) |
| 주소 검색을 닫는다 · 좌표를 못 찾는다 | 칸 그대로 · 못 찾으면 공통 오류 팝업 | — (공통 주소 검색 — 입점 신청과 같다) |
| 서버가 거절한다 | 받은 문구(칸 오류는 칸 옆) | — (공통 실패 처리) |

## 데이터 변화

- 승인(2)은 입점 신청을 승인으로 바꾸고, 업체와 업체 총관리자 계정을 만들고, 대표자 휴대폰으로 승인 문자를 보낸다(백엔드). 반려는 신청을 반려로 바꾸고 사유를 남긴다.
- 업체 상세(4)는 업체 정보 · 상태(영업중지 사유) · 영업중 여부를 바꾼다(백엔드 큐). 탈퇴는 되돌릴 수 없고 그 업체 업체 관리자 계정을 모두 정지한다. 영업중지 · 탈퇴 업체는 이용자 지도에서 빠진다.
- 화면이 따로 저장하는 값은 없다.

- 입점 신청 상태 배지 색(대기 · 승인 · 반려)은 이용자 입점 신청(`src/app/(user)/store-applications/store-application-format.ts` `applicationStateTone`)과 관리자가 함께 쓰게 된다 — 두 영역이 쓰는 곳으로 옮긴다(plan 에서).
