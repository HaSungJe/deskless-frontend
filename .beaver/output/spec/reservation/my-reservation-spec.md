# 내 예약

## 한눈에

- **무엇을** 이용자가 내 예약을 목록과 한 건으로 보고, 이용 전에는 취소 · 결제를, 이용 중에는 문 QR · 연장을 하며, 업체의 이용 중 취소 요청에 승인 · 거절한다.
- **왜** 예약 · 결제(Phase 7)를 해도 예약을 다시 보거나 취소 · 입실 · 연장할 화면이 없다. 백엔드가 보내는 SMS 링크(예약 1건 · 취소 동의)도 열 곳이 없다.
- **범위 밖** 예약 · 결제 화면(Phase 7 — 함께 build · ship), 업체 쪽 취소 요청 보내기 · 호실 바꾸기(매니저 화면).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 내 예약 목록 | 예약 카드를 쪽마다 보여 주고 예약 1건으로 보낸다 | 1건 |
| 2. 예약 1건 | 상태에 맞는 QR · 버튼 · 환불 안내를 보여 주고 취소 · 결제한다 | 16건 |
| 3. 이용 중 취소 동의 | 업체의 취소 요청에 기한 안에 승인 · 거절한다 | 4건 |
| 4. 연장 | 연장할 수 있으면 신청 뒤 결제위젯을 연다 | 3건 |

## 1. 내 예약 목록 — `PAGE /reservation`

**동작 흐름**

1. 로그인한 이용자의 예약을 한 쪽에 20개씩, 입실이 최근인 순으로 불러온다.
2. 카드마다 업체 · 상태 배지 · 객실 · 상품 · 이용 시간 · 합계를 보여 주고, 누르면 예약 1건으로 간다.
3. 예약한 호실이 사용중지된 확정 · 이용 중 예약은 카드에 "전액 환불로 취소할 수 있어요"를 띄운다.
4. 페이지 탭을 누르면 그 쪽을 다시 불러오고, 예약이 없으면 지도로 안내한다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| 쪽 | | 화면 상태(1부터) — 주소에 남기지 않는다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 예약이 있다 | 1쪽 카드(업체 · 상태 · 이용 시간 · 합계), 카드 링크는 예약 1건, 사용중지 호실이면 경고 | ✓ 정상 |
| 페이지 탭을 누른다 | 그 쪽을 다시 불러온다 | — (공통 페이지 탭) |
| 예약이 없다 | "아직 예약이 없어요" · 지도에서 찾기 | — (공통 빈 안내) |
| 로그인하지 않았다 | 로그인 화면 → 이 주소로 돌아옴 | — (공통 로그인 가드) |

## 2. 예약 1건 — `PAGE /reservation/[reservation_id]`

**동작 흐름**

1. 예약을 불러온다. 없거나 남의 예약이면 "예약을 찾을 수 없습니다." 안내 뒤 내 예약으로 보낸다.
2. 상태 띠에 상태와 한 줄 안내를 보여 주고, 예약 내용 · 결제 구간 · 환불 안내를 그린다.
3. 이용 중이면 문 QR 을 불러와 보여 준다. 이용 전이면 QR 을 잠가 두고(시작 1시간 안이면 남은 시간), 환불 마감 · 시작 · 끝 시각이 되면 버튼 · 안내를 다시 맞추거나 상세를 다시 불러온다.
4. 취소하면 사유를 받아 취소(큐)하고, 돌려받는 금액을 알린 뒤 다시 불러온다.
5. 결제 대기 구간이 마감 전이면 결제하기로 결제위젯을 열고, 이용 중이면 연장하기로 연장 화면에 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `reservation_id` | ✓ | 주소의 예약 — 백엔드 SMS 링크가 여는 고정 주소 |
| `cancel_reason` | 취소할 때 ✓ | 취소 사유(255자) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 이용 중인 예약을 연다 | 문 QR · QR 유효 끝 · 연장하기 | ✓ 정상 |
| 이용 전 확정 예약을 연다 | QR 을 부르지 않고 "시작 시각부터 QR 이 열립니다" | ✓ 정상 |
| 사유를 적고 취소한다 | 취소(큐) 1번 → 돌려받는 금액 팝업 → 다시 불러온다 | ✓ 정상 |
| 결제 대기 구간을 결제한다 | 결제위젯(주문명 "업체 호실", 돌아올 곳 이 화면) | — (위젯에 값을 넘기기만) |
| 결제 대기 마감이 지난다 | "결제 시간이 지나 예약이 만료됐어요." → 내 예약(만료된 예약은 상세가 404) | — (그리기 · 이동만) |
| 이용 중 사용중지 호실을 취소한다 | 다시 불러온 뒤 QR 을 또 부르지 않는다 | — (리뷰 회귀 — plan 테스트) |
| 화면을 열어 둔 채 시작 · 끝 시각이 된다 | 상세를 다시 불러 QR · 버튼을 맞춘다(시작 뒤에도 확정이면 10초 뒤 다시, 5분까지) | — (리뷰 회귀 — plan 테스트) |
| 사유가 비었거나 너무 길다 | 확인 버튼이 막히고 255자에서 잘린다 | — (공통 사유 입력 창) |
| 취소가 실패한다 · 늦어진다 | 사유 팝업 / 늦어짐 팝업 → 창을 닫고 다시 불러온다(칸 옆 오류면 창을 둔다) | — (큐 실패 공통 처리) |
| 없거나 남의 예약이다 | "예약을 찾을 수 없습니다." → 내 예약 | — (업체 상세와 같은 처리) |
| 로그인하지 않았다 | 로그인 화면 → 이 주소로 돌아옴 | — (공통 로그인 가드) |

**계산 규칙 — 예약 화면의 버튼과 QR** `reservationActions`

검증: 예약 상태와 지금 시각에 맞는 버튼만 보이고, QR 은 이용 중에만 열린다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 결제 대기이고 결제 마감 전이면 취소와 결제하기가 보인다 | `결제 대기 · 구간 마감 10분 뒤` | `{cancel: true, pay: true, qr: 'none'}` |
| 확정 예약이 2시간 뒤 시작하면 취소할 수 있고 QR 은 잠겨 있다 | `예약 확정 · 시작 2시간 뒤` | `{cancel: true, qr: 'locked', startsSoon: false}` |
| 시작까지 1시간이 안 남으면 남은 시간을 보여 준다 | `예약 확정 · 시작 30분 뒤` | `startsSoon: true` |
| 시작 시각이 지나면 아직 확정 상태여도 취소할 수 없다 | `예약 확정 · 시작 1분 지남` | `cancel: false` |
| 이용 중이면 QR 이 열리고 연장할 수 있지만 취소는 안 된다 | `이용 중` | `{cancel: false, qr: 'open', extend: true}` |
| 예약한 호실이 사용중지되면 이용 중에도 취소할 수 있다 | `이용 중 · 호실 사용중지` | `cancel: true` |

**계산 규칙 — 취소하면 돌려받는 금액 안내** `refundGuide`

검증: 환불 마감과 이용 시작을 기준으로 줄을 나누고, 지금 해당하는 줄을 강조한다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 결제 전에는 세 줄을 보여 주고, 마감 전 줄이 지금이며 금액은 붙지 않는다 | `결제 대기 · 마감 17:00 · 시작 19:00 · 30% · 지금 16:00` | `['11월 12일(목) 17:00 전 취소 — 전액 환불'(지금), '11월 12일(목) 17:00 ~ 19:00 취소 — 30% 환불', '11월 12일(목) 19:00 이용 시작 뒤 — 취소할 수 없음']` |
| 확정 예약을 마감과 시작 사이에 보면 비율 줄이 지금이고 받을 금액이 붙는다 | `예약 확정 · 합계 15,000원 · 30% · 지금 18:00` | 둘째 줄 `'30% 환불 · 4,500원'`(지금) |
| 마감 뒤에도 전액 환불이면 시작 전 · 시작 뒤 두 줄만 보여 준다 | `예약 확정 · 마감 뒤 100% · 지금 16:00` | `['11월 12일(목) 19:00 이용 시작 전 취소 — 전액 환불 · 15,000원'(지금), '11월 12일(목) 19:00 이용 시작 뒤 — 취소할 수 없음']` |
| 이용 중에는 줄 없이 취소할 수 없다는 문구만 보여 준다 | `이용 중` | `'이용이 시작되어 취소할 수 없어요.'` |

**계산 규칙 — 취소 뒤 안내 문구** `cancelResultMessage`

검증: 돌려받는 금액에 따라 금액 없음 · 환불 없음 · 환불 금액을 알린다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 결제 전에 취소하면 취소됐다고만 알린다 | `null` | `'예약을 취소했어요.'` |
| 돌려받을 돈이 0원이면 환불이 없다고 알린다 | `0` | `'예약을 취소했어요. 환불할 금액은 없어요.'` |
| 돌려받을 돈이 있으면 금액을 알린다 | `9000` | `'예약을 취소했어요. 9,000원을 환불해 드려요.'` |

## 3. 이용 중 취소 동의 — `PAGE /reservation/[reservation_id]/cancel-request`

**동작 흐름**

1. 업체의 취소 요청을 불러와, 요청 중이고 만료 전일 때만 업체 사유 · 환불 금액 · 남은 시간과 승인 · 거절을 보여 준다.
2. 답할 수 없으면(이미 처리됨 · 만료 · 없음) 안내한 뒤 예약 1건으로 보낸다.
3. 승인하면 승인(큐) 뒤 돌려받는 금액을, 거절하면 예약이 이어진다는 안내를 띄우고 예약 1건으로 간다.
4. 남은 시간이 다 되면 만료 안내 뒤 예약 1건으로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `reservation_id` | ✓ | 주소의 예약 — 업체가 보낸 SMS 링크가 여는 고정 주소 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 기한 안에 승인한다 | 승인(큐) 1번 → "취소를 승인했어요. N원을 환불해 드려요." → 예약 1건 | ✓ 정상 |
| 이미 처리됐거나 만료된 요청을 연다 | 승인 · 거절 없이 "이미 처리되었거나 만료된 요청이에요." → 예약 1건 | ✓ 실패 |
| 거절한다 | 거절(큐) → "취소 요청을 거절했어요. 예약은 그대로 이어져요." → 예약 1건 | — (승인과 같은 흐름) |
| 보는 사이 남은 시간이 다 된다 | "요청이 만료되었어요." → 예약 1건(승인 · 거절 중이면 그 결과로) | — (공통 남은 시간 표시) |
| 승인 · 거절이 실패한다 | 사유 팝업, 버튼 다시 열림 | — (큐 실패 공통 처리) |

**계산 규칙 — 취소 요청에 답할 수 있는지** `canAnswerCancelRequest`

검증: 업체가 요청 중이고 지금이 만료 시각 전일 때만 승인 · 거절할 수 있다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 요청 중이고 만료 5분 전이면 답할 수 있다 | `요청 중 · 만료 5분 뒤` | `true` |
| 만료 시각이 되면 요청 중이어도 답할 수 없다 | `요청 중 · 만료 시각 = 지금` | `false` |

## 4. 연장 — `PAGE /reservation/[reservation_id]/extension`

**동작 흐름**

1. 예약과 연장 조회를 함께 불러온다. 연장 조회는 시간대를 잡아 두지 않는다.
2. 연장할 수 있으면 지금 끝 → 연장 뒤 끝 · 늘어나는 길이 · 추가 금액 · 5분 안에 결제하라는 안내를 보여 준다.
3. 연장 신청(큐)이 되면 같은 화면에서 결제위젯을 연다. 결제가 끝나면 결제 결과 → 예약 1건으로 간다.
4. 연장할 수 없으면 사유와 지금 이용 끝을 보여 주고 연장 신청을 막는다. 이용 제한 · 탈퇴 대기 회원도 막는다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `reservation_id` | ✓ | 주소의 예약 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 연장할 수 있어 연장 신청한다 | 연장 신청(큐) 1번 → 결제위젯(돌아올 곳 예약 1건) | ✓ 정상 |
| 연장할 수 없다 | "연장할 수 없어요" · 사유 · 지금 이용 끝, 연장 신청 막힘 | — (받은 사유를 그리기만) |
| 이용 제한 · 탈퇴 대기 회원이다 | 회원 상태 띠, 연장 신청 막힘(서버도 거절) | — (공통 회원 상태 띠) |
| 연장 신청이 실패한다 · 늦어진다 | 팝업 → 연장 조회를 다시 | — (큐 실패 공통 처리) |
| 연장 조회를 못 불러온다 | "연장 정보를 불러오지 못했어요" · 다시 불러오기(옛 금액을 남기지 않음) | — (조회 실패 공통) |
| 결제 마감 5분이 지났다 | 연장 조회를 다시(그 예약은 다시 연장할 수 없다고 서버가 알려 줌) | — (결제위젯이 마감을 알림) |

**계산 규칙 — 연장 길이 글자** `extensionLengthLabel`

검증: 하루 단위면 일로, 아니면 시간과 분으로 얼마나 더 쓰는지 보여 준다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 하루를 연장하면 "1일 더"로 쓴다 | `(13일 11:00, 14일 11:00)` | `'1일 더'` |
| 1시간 30분이면 시간과 분을 함께 쓴다 | `(14:30, 16:00)` | `'1시간 30분 더'` |
