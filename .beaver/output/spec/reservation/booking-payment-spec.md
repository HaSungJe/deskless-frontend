# 예약 · 결제

## 한눈에

- **무엇을** 이용자가 업체 상세에서 상품 · 날짜 · 객실 그룹 · 시간대 · 호수를 골라 예약하고, 5분 안에 토스로 결제하면 예약이 확정된다.
- **왜** 업체를 둘러볼 수는 있지만(Phase 6) 예약하고 결제할 화면이 없다.
- **범위 밖** 내 예약 · 취소 · 연장(Phase 8 — 함께 build · ship), 업체 쪽 예약 관리(매니저 화면).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 예약 화면 | 상품 · 날짜 · 시간대 · 호수를 골라 예약하고 결제창을 연다 | 21건 |
| 2. 결제 성공 | 토스 승인 → 결제 확인을 한 번만 하고 결과를 보여 준다 | 3건 |
| 3. 결제 실패 | 토스가 돌려준 사유를 보여 주고 결제한 예약으로 보낸다 | 0건 |

## 1. 예약 화면 — `PAGE /stores/[store_id]/booking`

**동작 흐름**

1. 업체 상세를 불러 판매 상품 탭을 만들고, 오늘과 예약이 열린 마지막 날로 달력을 그린다.
2. 상품 · 날짜 · 박수가 바뀔 때마다 그날 예약할 수 있는 객실 그룹 · 시간대 · 호수를 다시 불러오고, 고른 것은 비운다.
3. 객실 그룹 카드를 넘겨 그룹을 고르고 시간대 · 호수를 고르면, 아래에 고른 내용과 결제 금액이 나온다.
4. 로그인한 이용자가 예약하기를 누르면 예약(큐)을 만든다. 실패하거나 늦어지면 안내한 뒤 빈 시간을 다시 불러온다.
5. 예약이 만들어지면 같은 화면이 결제 대기로 바뀌고(호실 · 상품은 예약하기를 누른 때의 것), 토스 결제위젯이 결제 마감 5분 안에 결제를 받는다. 요청 중에는 고르기를 막는다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_id` | ✓ | 주소의 업체 |
| `room_group_id` | | 업체 상세의 객실 그룹 카드에서 왔으면 그 그룹 카드부터 보여 준다 |
| 상품 · 날짜 · 박수 · 시간대 · 호수 | ✓ | 화면에서 고른다(박수는 연박만) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 상품 · 날짜 · 시간대 · 호수를 골라 예약한다 | 예약(큐) 1번 → 결제 대기 화면, 결제위젯에 결제 정보와 돌아올 곳(그 예약 1건) | ✓ 정상 |
| 그 사이 다른 사람이 같은 시간대를 잡았다 | 실패 사유 팝업 → 빈 시간을 다시 불러온다 | ✓ 실패 |
| 처리가 늦어진다 | "처리가 늦어지고 있어요" 팝업 → 빈 시간을 다시 불러온다 | — (실패와 같은 다시 불러오기) |
| 로그인하지 않고 예약하기를 누른다 | 로그인 화면 → 로그인 뒤 이 화면으로 돌아와 다시 고른다 | — (공통 로그인 주소) |
| 이용 제한 · 탈퇴 대기 회원이다 | 회원 상태 띠, 예약하기 막힘(서버도 거절) | — (공통 회원 상태 띠) |
| 호수까지 고르지 않았다 | 예약하기 막힘 | — (버튼이 열리지 않음) |
| 결제 마감 5분이 지났다 | 고르기로 돌아가 빈 시간을 다시 불러온다 | — (결제위젯이 마감을 알림) |
| 없는 업체다 | "업체를 찾을 수 없습니다." → 첫 화면 | — (업체 상세와 같은 처리) |
| 이미 고른 날짜 · 박수를 다시 누른다 | 그대로(다시 부르지 않음) | — (리뷰 회귀 — plan 테스트) |
| 예약 요청 중에 다른 호수 · 날짜를 누른다 | 그대로, 결제 화면은 누른 때의 호실 · 상품 | — (리뷰 회귀 — plan 테스트) |
| 예약 가능 시간을 못 불러온다 | "불러오지 못했어요" · 다시 불러오기 | — (조회 실패 공통) |
| 판매 상품이 없는 업체다 | "지금 예약할 수 있는 상품이 없어요" · 업체로 돌아가기 | — (그리기만) |

**계산 규칙 — 예약할 수 있는 마지막 날** `lastOpenDate`

검증: 지금 시각에 업체가 정한 예약 열림 시간을 더해, 한국 날짜로 그날까지만 고를 수 있다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 10일 오후 2시에 72시간 열림이면 13일까지 고를 수 있다 | `('2026-11-10T05:00:00.000Z', 72)` | `'2026-11-13'` |
| 밤 11시 30분에 1시간 열림이면 자정을 넘겨 다음 날까지 열린다 | `('2026-11-10T14:30:00.000Z', 1)` | `'2026-11-11'` |

**계산 규칙 — 달력 칸 배치** `buildMonthCells`

검증: 1일의 요일만큼 앞을 비우고, 그 달의 날 수만큼 날짜를 채운다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 2028년 2월은 화요일에 시작하는 윤년이라 빈칸 두 개 뒤 29일까지 채운다 | `'2028-02'` | 빈칸 2 · `'2028-02-01'` ~ `'2028-02-29'` |

**계산 규칙 — 날짜를 고를 수 있는지** `dayState`

검증: 지난 날 · 아직 예약이 안 열린 날 · 그 상품을 팔지 않는 요일은 고를 수 없고, 나머지는 고를 수 있다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 어제는 지난 날이라 고를 수 없다 | `('2026-11-09', 오늘 '2026-11-10', 마지막 '2026-11-13', 매일)` | `'past'` |
| 예약이 열린 마지막 날까지는 고를 수 있다 | `('2026-11-13', 오늘 '2026-11-10', 마지막 '2026-11-13', 매일)` | `'open'` |
| 마지막 날 다음 날은 아직 예약이 안 열렸다 | `('2026-11-14', 오늘 '2026-11-10', 마지막 '2026-11-13', 매일)` | `'not-open'` |
| 그 상품을 팔지 않는 요일은 고를 수 없다 | `('2026-11-11', 오늘 '2026-11-10', 마지막 '2026-11-13', 일요일만)` | `'closed'` |

**계산 규칙 — 달 넘기기** `monthNav`

검증: 오늘의 달보다 앞으로, 예약이 열린 마지막 날의 달보다 뒤로는 넘길 수 없다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 열린 날이 다음 달까지 이어지면 이번 달에서는 다음 달로만 넘길 수 있다 | `('2026-11', 오늘 '2026-11-30', 마지막 '2026-12-03')` | `{prev: false, next: true}` |

**계산 규칙 — 처음 고르는 날짜** `initialDate`

검증: 오늘을 고를 수 있으면 오늘, 아니면 열린 날 가운데 가장 이른 날로 시작한다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 오늘 고를 수 있으면 오늘로 시작한다 | `('2026-11-10', 마지막 '2026-11-13', 매일)` | `'2026-11-10'` |
| 오늘 팔지 않으면 열린 날 가운데 가장 이른 날로 시작한다 | `('2026-11-10', 마지막 '2026-11-13', 수요일만)` | `'2026-11-11'` |

**계산 규칙 — 예약 요청에 담는 값** `toReservationDto`

검증: 시간 이용은 한국 시각의 시작 시각이나 "지금 바로"를, 연박은 박수를 함께 보낸다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 시간 이용은 고른 시간대의 시작을 한국 시각으로 보낸다 | `시간 이용 · 10일 · 시작 '2026-11-10T05:30:00.000Z' · 호수 r1` | `{room_id: 'r1', room_plan_type_id: 'HOURLY', date: '2026-11-10', start_time: '14:30'}` |
| 지금 바로 칸을 고르면 시작 시각 대신 지금 바로를 보낸다 | `시간 이용 · 지금 바로 칸` | `{…, is_now: 1}` (시작 시각 없음) |
| 연박은 박수를 함께 보낸다 | `연박 · 3박` | `{…, room_plan_type_id: 'LONG', nights: 3}` |

**계산 규칙 — 시간대 칩 글자** `slotLabel`

검증: 지금 바로 칸은 시작 ~ 끝을, 1박 · 연박은 입실 시각과 퇴실 날짜 · 시각을 보여 준다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 지금 바로 칸은 "지금 바로" 아래에 시작 ~ 끝을 쓴다 | `시간 이용 · 지금 바로 · 14:12 ~ 17:12` | `{main: '지금 바로', sub: '14:12 ~ 17:12'}` |
| 1박은 입실 시각과 다음 날 퇴실 날짜 · 시각을 쓴다 | `1박 · 10일 20:00 ~ 11일 11:00` | `{main: '20:00 입실', sub: '~ 11월 11일 11:00 퇴실'}` |

**계산 규칙 — 이용 시간 글자** `formatDateTimeRange`

검증: 한국 시각으로 쓰고, 같은 날이면 끝은 시각만, 날이 바뀌면 끝에도 날짜와 요일을 쓴다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 한국 날짜가 같으면 끝은 시각만 쓴다(UTC 로는 전날이어도) | `('2026-11-10T15:30:00.000Z', '2026-11-10T18:30:00.000Z')` | `'11월 11일(수) 00:30 ~ 03:30'` |
| 1박처럼 날이 바뀌면 끝에도 날짜와 요일을 쓴다 | `('2026-11-14T11:00:00.000Z', '2026-11-15T02:00:00.000Z')` | `'11월 14일(토) 20:00 ~ 11월 15일(일) 11:00'` |

**계산 규칙 — 구간 시간 글자** `formatTimeRange`

검증: 시각 위주로 쓰고, 끝이 다음 날이면 "다음 날", 그보다 뒤면 끝에 날짜를 붙인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 끝이 다음 날이면 "다음 날"을 붙인다 | `('2026-11-09T11:00:00.000Z', '2026-11-10T02:00:00.000Z')` | `'20:00 ~ 다음 날 11:00'` |
| 이틀 넘게 뒤면 끝에 날짜를 쓴다 | `('2026-11-10T11:00:00.000Z', '2026-11-13T02:00:00.000Z')` | `'20:00 ~ 11월 13일 11:00'` |

## 2. 결제 성공 — `PAGE /payments/success`

**동작 흐름**

1. 토스가 붙여 준 결제 키 · 주문 번호 · 금액으로 토스 승인(우리 서버)을 한 번만 요청한다.
2. 승인되면 백엔드에 결제 확인(큐)을 보내 예약을 확정한다.
3. 확정되면 "예약이 확정되었어요"와 예약 보기를, 거절되면 사유와 예약으로 돌아가기를 보여 준다.
4. 토스 쪽 장애면 다시 확인을, 확인이 늦어지면 내 예약으로 가는 길을 준다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `paymentKey` · `orderId` · `amount` | ✓ | 토스 결제창이 붙여 준 값 그대로 |
| `return_url` | | 결제한 예약 1건(예약 · 결제하기 · 연장 모두) — 예약으로 돌아가기 주소 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 토스가 승인하고 결제 확인이 된다 | "예약이 확정되었어요" · 상태 배지 · 예약 보기(예약 1건) | ✓ 정상 |
| 토스가 승인을 거절한다 | 사유 · 예약으로 돌아가기(돌아갈 주소), 결제 확인을 부르지 않음 | ✓ 실패 |
| 토스 쪽 장애로 승인 결과를 모른다 | "결제를 확인하지 못했어요" · 다시 확인 | — (승인 route 가 알려 줌, Phase 4) |
| 결제 확인이 실패한다 | 실패 화면(사유 · 오류 코드 · 예약으로 돌아가기) | — (토스 거절과 같은 화면) |
| 결제 확인이 늦어진다 | "처리가 늦어지고 있어요" · 내 예약 | — (큐 늦어짐 공통) |
| 주소 값이 빠졌다 | 실패 화면 | — (그리기만) |
| 로그인이 풀렸다 | 로그인 화면 → 이 주소로 돌아옴 | — (공통 로그인 가드) |

**계산 규칙 — 결제 뒤 돌아갈 주소** `paymentReturnPath`

검증: 토스가 뒤에 붙인 값을 떼고 우리 주소만 돌아갈 곳으로 쓴다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 토스가 우리 주소 뒤에 ? 로 값을 붙여도 앞의 우리 주소만 쓴다 | `'/reservation/abc/extension/?code=PAY_PROCESS_CANCELED'` | `'/reservation/abc/extension/'` |

## 3. 결제 실패 — `PAGE /payments/fail`

**동작 흐름**

1. 토스가 붙여 준 실패 사유 · 오류 코드를 화면에 보여 준다. 오류 팝업은 띄우지 않는다(이용자가 결제창을 닫은 경우 포함).
2. 예약으로 돌아가기는 결제한 예약 1건(돌아갈 주소)으로 보낸다 — 결제 마감 전이면 거기서 다시 결제하거나 취소한다. 없거나 다른 사이트 주소면 "처음으로"(첫 화면).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `code` · `message` | | 토스 오류 코드 · 사유 |
| `return_url` | | 결제한 예약 1건 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 결제창에서 실패하거나 닫았다 | "결제하지 못했어요" · 사유 · 오류 코드 · 예약으로 돌아가기 | — (받은 값을 그리기만) |
