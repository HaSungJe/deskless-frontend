# 여행 도우미 — AI 대화로 숙소 찾기

## 한눈에

- **무엇을** 이용자가 지도 화면의 "여행 도우미" 버튼으로 대화창을 열어 말로 여행지 · 숙소를 묻고, AI 답(글자 단위로 흘러옴)과 추천 업체 카드(최대 3곳)를 받는다. 하루 질문 수가 정해져 있고 대화를 초기화할 수 있다.
- **왜** 조건을 하나하나 고르지 않고 말로 숙소를 찾게 한다(백엔드 수정 요청 `frontend/changes/2026-11-25-chat-ai-search.md` — 새 API 4개, 질문은 새 방식 SSE 스트림).
- **범위 밖** 카드 안 작은 지도 · 길찾기, 대화 여러 개(대화방 목록), 답 다시 만들기, 마크다운 전체(굵게 · 목록만 그린다).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 지도 여행 도우미 버튼 | "가까운 순" 자리에 버튼 — 로그인했으면 대화창, 아니면 로그인 | 1건 |
| 2. 여행 도우미 대화 보기 | 이전 대화 · 카드 · 오늘 남은 질문 수 | 1건 |
| 3. 여행 도우미 질문 보내기 | 스트림(진행 → 카드 → 글 → 완료) · 막는 이유 · 굵게 · 목록 | 15건 |
| 4. 여행 도우미 대화 초기화 | 확인 → 초기화(큐) → 대화 비움(질문 수는 그대로) | 1건 |

## 1. 지도 여행 도우미 버튼 — `PAGE /`

**동작 흐름**

1. **버튼 보이기** — 목록 머리의 "가까운 순" 글자를 빼고 그 자리에 "여행 도우미" 버튼을 둔다.
2. **열기** — 로그인했으면 대화창(`/chat/`)을 지도 위 팝업으로 연다.
   - 로그인 전이면 → 로그인 화면으로, 로그인 뒤 대화창(`/chat/`)으로 돌아온다

**입력**

|---|---|---|
| (없음) | | 버튼만 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 로그인한 이용자 · 로그인 전 이용자가 지도를 연다 | 로그인했으면 버튼 주소가 `/chat/`, 로그인 전이면 로그인 주소(돌아올 곳 `/chat/`) · "가까운 순" 글자 없음 | ✓ 정상 |

## 2. 여행 도우미 대화 보기 — `PAGE /chat`

**동작 흐름**

1. **열기** — 지도에서 누르면 지도 위 팝업, 주소로 바로 들어오면 보통 화면으로 연다(로그인한 이용자만).
2. **대화 읽기** — 대화 보기를 한 번 읽어 이전 질문 · 답 · 업체 카드(오래된 순)와 오늘 남은 질문 수를 그린다.
   - 대화한 적이 없으면 → 첫 안내("어디로 떠나고 싶으세요?" · 예시 질문)
   - 못 읽었으면 → 받은 문구 · 다시 불러오기
3. **다시 보기** — 화면에 돌아오면(다른 탭에서 돌아옴) 남은 질문 수만 다시 읽는다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| (없음) | | 로그인한 이용자의 대화 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 이전 대화가 있는 이용자가 연다 | 대화 보기 1번 → 질문 · 답 말풍선(오래된 순) · 답에 붙은 업체 카드(사진 · 상호명 · 주소 · 편의시설 칩 — 누르면 업체 상세) · "오늘 남은 질문 3회" | ✓ 정상 |
| 대화한 적이 없다 | 첫 안내 · 예시 질문 | — (보여 주기만) |
| 대화를 못 읽었다 | 받은 문구 · 다시 불러오기 | — (공통 실패 처리) |
| 다른 탭에서 돌아온다 | 남은 질문 수 1번 다시 | — (브라우저 이벤트 — 손으로 확인) |

## 3. 여행 도우미 질문 보내기 — `PAGE /chat`

**동작 흐름**

1. **쓰기** — 아래 입력칸에 질문(100자까지 · 글자 수 표시)을 쓴다. 보내기를 막는 이유가 있으면 칸 · 버튼을 막고 그 이유를 보인다(아래 계산 규칙).
2. **보내기** — 보내면 내 질문을 바로 말풍선으로 붙이고 질문 보내기(스트림)를 부른다.
   - 시작 전에 거절되면 → 429 는 남은 질문 0 으로 막고 다시 채워지는 시각 안내, 400 은 칸 옆, 409 · 503 은 오류 팝업
3. **받기** — 스트림 이벤트를 차례로 AI 말풍선에 반영한다 — 진행 표시 → 업체 카드 → 답 글 이어 붙이기 → 완료(아래 계산 규칙).
   - 도중에 실패하면 → AI 말풍선을 "답을 받지 못했어요" 로 바꾼다(질문 수는 그대로)
4. **마치기** — 완료되면 저장된 답 · 카드로 말풍선을 맞추고 "오늘 남은 질문 N회" 를 바꾼다. 답 글의 굵게 · 목록은 그려 보인다(아래 계산 규칙).
5. **떠나기** — 답을 받는 중에 대화창을 닫거나 다른 화면으로 가면 요청을 끊는다(서버도 멈추고 저장 · 횟수 없음).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `content` | ✓ | 질문(1 ~ 100자) — 앞뒤 빈칸은 뗀다, 비면 보내기 버튼이 꺼진다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| "온천 가고 싶은데 갈 만한 데 있을까?" 를 보낸다 | 질문 보내기 1번(`{content}`) → 내 말풍선 → 진행 표시 → 카드 → 글이 이어 붙는다 → 완료 글 · 카드 · "오늘 남은 질문 2회" · 입력칸 비움 | ✓ 정상 |
| 오늘 질문을 다 쓴 뒤 보낸다(429) | 입력칸 · 버튼 막힘 · "오늘 질문을 모두 사용했어요. 11월 26일(목) 00:00에 다시 채워져요." · 내 말풍선 지움 | ✓ 실패 |
| 답을 받는 중에 대화창을 닫는다 | 요청 끊김(취소 신호) | ✓ 정상 |
| 앞뒤 빈칸뿐이다 · 100자를 넘는다 | 생기지 않는다 | — (빈 값이면 버튼이 꺼지고, 칸이 100자에서 멈춘다) |
| 다른 기기 · 탭에서 보낸 질문에 답하는 중이다(409) · 서버가 바쁘다(503) | 받은 문구(오류 팝업) · 내 말풍선 지움 | — (공통 실패 처리) |
| 답 도중 실패한다(`failed`) | AI 말풍선 "답을 받지 못했어요" | — (계산 규칙) |

**계산 규칙 — 스트림으로 답 만들기**

검증: 이벤트가 오는 대로 진행 문구 · 카드 · 글이 쌓이고, 완료되면 저장된 답과 남은 질문 수로 맞춰지며, 실패하면 보이던 글을 지우고 실패 문구가 된다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 진행 단계가 오면 그 단계의 문구가 보인다 | 웹 검색 단계 | `웹에서 찾고 있어요…` |
| 업체 카드가 오면 카드가 붙는다 | 카드 2곳 | 카드 2곳 · 글은 아직 비어 있음 |
| 글 조각이 오면 이어 붙는다 | "온천은 " 다음 "부산 쪽이에요" | `온천은 부산 쪽이에요` |
| 완료되면 저장된 답과 남은 질문 수로 맞춘다 | 저장된 글 · 카드 1곳 · 남은 질문 2회 | 글 · 카드가 저장된 값 · 진행 문구 없음 · 남은 질문 2회 |
| 도중에 실패하면 실패 문구만 남는다 | 글 조각 뒤 실패 | 글 · 카드 없음 · `답을 받지 못했어요. 잠시 후 다시 물어봐 주세요.` |

**계산 규칙 — 보내기를 막는 이유**

검증: 이 화면에서 답을 받는 중 · 오늘 다 씀 · 다른 곳에서 답하는 중이면 그 이유로 막고, 아니면 막지 않는다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 이 화면에서 답을 받는 중이면 막는다 | 받는 중 · 남은 3 | `답을 받고 있어요.` |
| 오늘 다 썼으면 다시 채워지는 시각을 알린다 | 남은 0 · 다시 채워지는 시각 내일 0시 | `오늘 질문을 모두 사용했어요. 11월 26일(목) 00:00에 다시 채워져요.` |
| 다른 곳에서 보낸 질문에 답하는 중이면 막는다 | 남은 3 · 다른 곳 답하는 중 | `다른 곳에서 보낸 질문에 답하고 있어요. 답이 끝난 뒤 보내 주세요.` |
| 막을 이유가 없으면 보낼 수 있다 | 남은 3 · 답하는 중 아님 | 막지 않음 |

**계산 규칙 — 답 글 굵게 · 목록**

검증: `**굵게**` 는 굵은 글자로, `- ` · `1. ` 로 시작하는 줄은 목록으로 그리고, 그 밖의 글자(태그처럼 보이는 글자 포함)는 그대로 글자다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 별표 두 개로 감싼 말은 굵게 보인다 | `부산 **해운대** 온천` | 한 문단 — `부산 ` · 굵은 `해운대` · ` 온천` |
| 줄머리 표시가 있는 줄은 목록이 된다 | `추천:` 다음 줄 `- 해운대` · `- 동래` | 문단 `추천:` · 목록 `해운대` · `동래` |
| 태그처럼 보이는 글자도 글자 그대로다 | `<b>굵게</b>` | 한 문단 — 글자 `<b>굵게</b>` 그대로 |

## 4. 여행 도우미 대화 초기화 — `PAGE /chat`

**동작 흐름**

1. **누르기** — 대화창의 "대화 초기화"를 누르면 확인 창("오늘 남은 질문 수는 그대로예요")이 뜬다.
   - 답을 받는 중이면 → 버튼을 막는다
2. **초기화** — 확인하면 대화 초기화(큐)를 부른다.
   - 서버가 거절하면 → 받은 문구
3. **비우기** — 끝나면 대화를 비우고 첫 안내를 보인다(남은 질문 수는 그대로).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| (없음) | | 내 대화 전부 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 대화가 있는 이용자가 초기화를 확인한다 | 확인 창 → 대화 초기화(큐) 1번 → 말풍선 없음 · 첫 안내 · 남은 질문 수 그대로 | ✓ 정상 |
| 확인 창에서 취소한다 | 부르지 않는다 | — (공통 확인 창) |
| 서버가 거절한다 | 받은 문구 | — (공통 실패 처리) |

## 데이터 변화

- 질문 보내기(3)는 완료되면 백엔드에 질문 · 답을 저장하고 오늘 질문 수를 하나 센다. 도중 실패 · 끊김은 저장도 세지도 않는다.
- 초기화(4)는 내 대화 이력을 모두 지운다(오늘 질문 수는 그대로).
- 대화는 7일 지나면 백엔드가 저절로 지운다(화면에 안내 한 줄). 화면은 따로 저장하는 값이 없다.

## 결정한 것

- [x] 지도 진입은 "가까운 순" 자리의 버튼 하나, 누르면 대화창이 열린다 — 사용자 선택. 이름은 버튼 · 대화창 제목 모두 "여행 도우미" — 사용자 선택(숙소뿐 아니라 여행지도 묻는다).
- [x] 대화창은 지도 위 팝업 + 주소 `/chat/`(경로 모달 — 지도에서 열면 팝업, 새로고침 · 직접 접속이면 보통 화면) — 사용자 선택(추천안). 로그인 전에 누르면 로그인 화면(돌아올 곳 `/chat/`).
- [x] 답 글은 굵게(`**`) · 목록(`- ` · `1. `)만 직접 그리고 나머지는 글자 그대로(줄바꿈 유지) — 사용자 선택(추천안). 패키지를 들이지 않는다.
- [x] 실패는 대화 안에서 — 도중 실패는 AI 말풍선 문구, 429 는 입력을 막고 다시 채워지는 시각, 400 은 칸 옆, 409 · 503 은 공통 오류 팝업 — 사용자 선택(추천안). 시작 전 실패면 방금 붙인 내 말풍선은 지운다(저장되지 않았다).
- [x] 여러 이벤트를 차례로 받는 스트림 함수는 이번 기능에 포함(`src/shared/api/stream.ts`) — 사용자 선택(추천안). SSE 자르기(`takeSseEvents`)는 큐와 같이 쓴다.
- [x] 진행 문구 — 웹 검색 "웹에서 찾고 있어요…" · 업체 찾기 "숙소를 고르고 있어요…" · 답 쓰기 "답을 쓰고 있어요…".
- [x] 업체 카드는 사진(없으면 기본 그림) · 상호명 · 주소 · 편의시설 칩(받은 순서 — 업체 편의시설 다음 객실 항목, 묶음 제목 없이), 누르면 업체 상세. 작은 지도 · 길찾기는 넣지 않는다.
- [x] 남은 질문 수는 대화창 머리에 "오늘 남은 질문 N회", 다른 탭에서 돌아오면 남은 질문 수만 다시 읽는다(요청서).
- [x] 계산 테스트 3개 — 스트림으로 답 만들기(5건) · 보내기를 막는 이유(4건) · 답 글 굵게 · 목록(3건) — 사용자 선택(추천안).
- [x] 첫 경로 모달이라 `@modal/page.tsx`(null)를 같이 둔다 — 팝업 안 링크로 홈에 가도 팝업이 남지 않게(docs/architecture.md "경로 모달" 미적용 줄).
