# 예약 현황 — 호실별 하루 막대 · 업체 취소 · 호실 이동

## 한눈에

- **무엇을** 업체 관리자가 콘솔의 "예약 현황"(`/manager/reservations`)에서 고른 날짜와 겹치는 예약을 호실별 하루(0시 ~ 24시) 막대로 보고, 막대를 눌러 업체 취소 · 호실 이동 · 이용 중 취소 요청을 한다.
- **왜** 콘솔 메뉴 "예약 현황"의 화면이 없어, 업체가 오늘 어느 호실에 누가 언제 쓰는지 보거나 예약을 옮기 · 취소할 길이 없다.
- **범위 밖** 예약 만들기 · 결제(이용자 U3 · U4), 호실 상태 바꾸기(M4 호실 — Phase 12), 매출 통계(M2 대시보드).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 예약 현황 | 날짜 고르기 · 호실별 막대 · 정비 꼬리 · 지금 선 · 막대 메뉴 | 12건 |
| 2. 업체 취소 | 시작 전 예약을 사유와 함께 취소(확정은 전액 환불) | 2건 |
| 3. 호실 이동 | 시작 전 확정 예약을 같은 그룹의 다른 호실로 | 4건 |
| 4. 이용 중 취소 요청 | 이용 중 예약에 예약자 동의 요청(10분) | 1건 |

## 1. 예약 현황 — `PAGE /manager/reservations`

**동작 흐름**

1. 화면을 열면 오늘(한국 날짜)의 현황을 불러온다. 머리에 날짜 칸 · 전날 / 다음 날 · "오늘" · "다시 불러오기", 아래에 색 안내(결제 대기 · 예약 확정 · 이용 중 · 이용 완료 · 정비시간 · 지금). 날짜를 바꾸면 그 날짜로 다시 불러온다.
2. 호실마다 한 줄(호실명 · 상태 배지 · "층 · 그룹")에 0시 ~ 24시 눈금, 그날과 겹치는 예약을 막대로 놓는다 — 입실 ~ 퇴실 위치 · 길이, 그날 밖으로 나가는 쪽은 하루 끝에서 잘라 ‹ · › 로 표시, 막대 뒤 점선 꼬리는 정비 포함 점유 끝까지. 막대에는 시간 글자 · "예약자 · 상품", 색은 예약 상태, 위에 이용 중 취소 요청 배지(요청 중 · 승인 · 거절 · 만료). 예약이 없으면 "예약 없음", 사용중지 호실은 옅게.
3. 고른 날짜가 오늘이면 지금 시각에 세로 선과 "지금 14:30".
4. 막대를 누르면 작은 대화상자("401호 예약" · 상태 배지)에 시간(점유 끝 포함) · 상품 · 예약자 · 휴대폰 · 금액과 업체 취소 · 호실 이동 · 이용 중 취소 요청 버튼 — 그 예약에 할 수 있는 것만 켜고, 안내("업체 취소 · 호실 이동은 시작 전 예약에만, 이용 중 취소 요청은 이용 중 예약에만 켜집니다.").
5. 버튼을 누르면 그 작업 대화상자(2 ~ 4)로 바뀐다. 작업이 끝나면 현황을 다시 불러온다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `date` | ✓ | 날짜(YYYY-MM-DD, 한국 날짜) — 처음은 오늘 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 다음 날로 넘긴다 | 현황 1번 더(그다음 날짜) | ✓ 정상 |
| 막대를 누른다 | 예약 대화상자(켜진 버튼만) | — (아래 작업 버튼 규칙이 확인) |
| 현황을 못 읽었다(다른 날짜로 넘긴 뒤 포함) | 받은 문구 팝업 · "예약 현황을 불러오지 못했어요" · 다시 불러오기, 전날 막대는 그리지 않음 | ✓ 읽기 실패(리뷰 261121 #1) |

**계산 규칙 — 막대 위치와 길이** `barGeometry`

검증: 예약이 고른 날의 몇 % 지점에서 시작해 몇 % 길이인지 정하고, 그날 밖으로 나간 쪽은 하루 끝에서 자르며 잘렸다고 표시하고, 정비 꼬리도 하루 안까지만 그린다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 하루 안의 예약은 시각대로 놓고 정비 꼬리를 붙인다 | 11-10 10:00 ~ 13:00, 점유 끝 13:30 · 11-10 | 왼쪽 41.667% · 길이 12.5%, 잘림 없음, 꼬리 54.167%부터 2.083% |
| 전날 시작한 예약은 0시부터로 자르고 왼쪽 잘림 | 11-09 21:00 ~ 11-10 11:00 · 11-10 | 왼쪽 0% · 길이 45.833%, 왼쪽 잘림 |
| 다음 날 끝나는 예약은 24시까지로 자르고 오른쪽 잘림 | 11-10 21:00 ~ 11-11 11:00 · 11-10 | 왼쪽 87.5% · 길이 12.5%, 오른쪽 잘림, 꼬리 없음 |
| 정비 꼬리가 자정을 넘으면 24시까지만 | 11-10 22:00 ~ 23:45, 점유 끝 11-11 00:15 · 11-10 | 꼬리 98.958%부터 1.042% |

**계산 규칙 — 막대 시간 글자** `barLabel`

검증: 하루 안이면 "시작~끝", 전날 시작이면 앞에 ‹ 와 시작 날짜, 다음 날 끝이면 뒤에 "다음 날" 과 › 를 붙인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 하루 안이면 시작~끝 시각 | 11-10 10:00 ~ 13:00 · 11-10 | `'10:00~13:00'` |
| 전날 시작이면 ‹ 와 시작 날짜 | 11-09 21:00 ~ 11-10 11:00 · 11-10 | `'‹ 11-09 21:00 ~ 11:00'` |
| 다음 날 끝이면 다음 날과 › | 11-10 21:00 ~ 11-11 11:00 · 11-10 | `'21:00 ~ 다음 날 11:00 ›'` |

**계산 규칙 — 작업 버튼 켜짐** `reservationActions`

검증: 시작 전 확정 예약은 업체 취소와 호실 이동을, 이용 중 예약은 취소 요청만 켜고, 예약자 휴대폰이 없거나 이미 요청 중이면 취소 요청을 끈다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 시작 전 확정 예약은 업체 취소 · 호실 이동 | 예약 확정 · 시작 1시간 뒤 | 업체 취소 · 호실 이동 켬, 취소 요청 끔 |
| 이용 중 예약은 취소 요청만 | 이용 중 · 휴대폰 있음 · 요청 없음 | 취소 요청만 켬 |
| 예약자 휴대폰이 없으면 취소 요청을 못 한다 | 이용 중 · 휴대폰 없음 | 모두 끔 |
| 이미 요청 중이면 다시 요청하지 않는다 | 이용 중 · 요청 중 | 모두 끔 |

## 2. 업체 취소 — `PAGE /manager/reservations`

**동작 흐름**

1. 대화상자("업체 취소")에 호실(호실 · 층 · 그룹) · 시간 · 상품 · 예약자 · 상태 · 결제 금액, "확정 예약은 결제 금액 전액(18,000원)을 환불합니다. 취소 사유는 예약자에게 가는 문자에 함께 나갑니다." 안내.
2. 취소 사유(255자 · 글자 수)를 받고 "업체 취소"를 누르면 검사해 칸 옆에 오류를, 맞으면 업체 취소(큐)를 보낸다.
3. 끝나면 닫고 현황을 다시 불러온다. 이미 시작한 예약이면 받은 문구를 대화상자 안 위험 띠 · 오류 팝업으로.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `cancel_reason` | ✓ | 취소 사유(255자) — 예약자 문자에 함께 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 사유를 넣고 업체 취소한다 | 업체 취소(큐) 1번(그 예약 — 다듬은 사유) → 닫힘 → 현황 다시 | ✓ 정상 |
| 사유를 비우고 업체 취소한다 | 칸 옆 "취소 사유를 입력해주세요.", 취소 0번 | ✓ 검증 실패 |
| 이미 시작한 예약이다 | 받은 문구 | — (공통 실패 처리) |

## 3. 호실 이동 — `PAGE /manager/reservations`

**동작 흐름**

1. 대화상자("호실 이동")에 지금 호실 · 시간 · 예약자, "옮길 호실 (같은 객실 그룹 · 그룹명)" 고르기 — 같은 그룹의 다른 호실(현황의 호실 목록에서), 사용중지 호실은 고를 수 없게("사용중지된 호실로는 옮길 수 없습니다."), 하나도 없으면 "같은 객실 그룹에 옮길 수 있는 호실이 없습니다."
2. "금액 · 시간은 그대로입니다. 옮길 호실의 그 시간(정비시간 포함)이 비어 있어야 합니다." 안내.
3. 호실을 고르고 "호실 이동"을 누르면 검사 뒤 호실 이동(큐)을 보낸다. 끝나면 닫고 현황을 다시 불러온다. 겹치는 예약이 있으면 받은 문구를 목록 아래에.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `room_id` | ✓ | 옮길 호실 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 303호를 골라 옮긴다 | 호실 이동(큐) 1번(그 예약 — 303호) → 닫힘 → 현황 다시 | ✓ 정상 |
| 옮길 호실에 겹치는 예약이 있다 | 받은 문구를 목록 아래에 | — (공통 실패 처리) |

**계산 규칙 — 옮길 호실 목록** `roomChangeOptions`

검증: 같은 객실 그룹의 호실만, 지금 호실은 빼고, 사용중지 호실은 고를 수 없게 넣는다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 같은 그룹 호실만 고른다 | 현황 호실 4개(같은 그룹 3 · 다른 그룹 1) · 지금 401호 | 다른 그룹 호실이 없다 |
| 지금 호실은 뺀다 | 같은 입력 | 401호가 없다 — 303호 · 402호 |
| 사용중지 호실은 고를 수 없다 | 같은 입력(402호 사용중지) | 402호는 고를 수 없음, 303호는 고를 수 있음 |

## 4. 이용 중 취소 요청 — `PAGE /manager/reservations`

**동작 흐름**

1. 대화상자("이용 중 취소 요청")에 호실 · 시간 · 예약자 · 상태(지난 요청 배지) · 결제 금액, "예약자에게 동의 링크 문자를 보냅니다. 10분 안에(예약 끝이 먼저면 예약 끝까지) 예약자가 승인하면 전액 환불로 취소됩니다. 결과는 예약 현황의 막대 배지로 확인합니다." 안내.
2. 취소 사유(255자 — 예약자 동의 화면에 보이고 승인되면 예약의 취소 사유)를 받고 "요청 보내기"를 누르면 검사 뒤 요청(큐)을 보낸다.
3. 끝나면 대화상자를 닫고 현황 위에 "취소 요청을 보냈습니다. 14:40까지 예약자 동의를 기다립니다." 띠(만료 시각 — 결과 없이 끝나면 시각 없이)를 보이고 현황을 다시 불러온다. 이미 진행 중이면 받은 문구.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `cancel_reason` | ✓ | 취소 사유(255자) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 사유를 넣고 요청을 보낸다 | 요청(큐) 1번(그 예약 — 다듬은 사유) → 닫힘 → "14:40까지" 띠 → 현황 다시 | ✓ 정상 |
| 사유를 비운다 | 칸 옆 "취소 사유를 입력해주세요.", 요청 0번 | — (업체 취소와 같은 검사) |
| 이미 진행 중인 요청이 있다 | 받은 문구 | — (공통 실패 처리) |

- [x] 막대를 누르면 시안의 펼침 창 대신 작은 대화상자 — 그 안의 버튼이 작업 대화상자로 바꾼다. 근거: 호실 상태 메뉴와 같은 결정(사용자 2026-11-20 — 공통 펼침 부품 없음).
- [x] 업체 취소는 시작 전의 결제 대기 · 예약 확정, 호실 이동은 시작 전 예약 확정, 이용 중 취소 요청은 이용 중(예약자 휴대폰이 있고 요청 중이 아닐 때)에만 켠다 — 백엔드가 막는 것을 미리 끈다. 근거: 지침서 M3 화면 주의 · DTO(`ReservationRoomChangeDto` "이용 시작 전 확정 예약만" · `ReservationStoreCancelDto` · `ReservationUseCancelRequestDto`) · 시안 "휴대폰이 null 이면 버튼을 미리 끈다".
