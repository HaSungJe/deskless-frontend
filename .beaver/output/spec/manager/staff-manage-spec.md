# 업체 관리자 — 목록 · 등록 · 상세 · 계정 관리

## 한눈에

- **무엇을** 업체 총관리자가 콘솔의 "업체 관리자"(`/manager/staff`)에서 이 업체 콘솔에 로그인하는 계정을 찾아보고, 새 계정을 등록하며(임시 비밀번호가 그 휴대폰으로 간다), 계정마다 정보 수정 · 비밀번호 초기화 · 정지 / 해제 · 삭제를 한다.
- **왜** 콘솔 메뉴 "업체 관리자"의 화면이 없어, 업체 총관리자가 직원 계정을 만들거나 막을 길이 없다.
- **범위 밖** M2 대시보드(Phase 14 의 #48 — Phase 10 과 함께 이미 배포), 관리자(총괄) 쪽 업체 관리자 관리(A5 — Phase 17), 업체 총관리자 자신의 계정 수정(비밀번호 변경은 M1 `/manager/password`).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 업체 관리자 목록 | 검색 · 표 · 등록 대화상자 — 업체 총관리자만 | 4건 |
| 2. 업체 관리자 상세 | 계정 정보 · 이름 · 휴대폰 · 성별 · 생년월일 수정 | 2건 |
| 3. 계정 관리 | 비밀번호 초기화 · 정지 / 해제 · 삭제 — 모두 확인 창 뒤 | 3건 |

## 1. 업체 관리자 목록 — `PAGE /manager/staff`

**동작 흐름**

1. 콘솔 틀이 계정 쿠키를 다 읽을 때까지는 아무것도 그리지 않는다. 읽은 계정이 업체 총관리자가 아니거나 없으면(계정 쿠키 없음) 목록을 부르지 않고 "업체 총관리자만 볼 수 있는 화면입니다." 안내만 보인다(메뉴도 숨겨져 있다 — 백엔드도 403).
2. 업체 총관리자면 업체 관리자를 한 쪽에 20개씩 불러와 표로 보인다(아이디 · 이름 · 휴대폰 · 권한 배지 · 상태 배지 · 비밀번호 변경 필요 · 등록일). 업체 총관리자 줄(내 계정)은 맨 위 · 옅은 면이고 상세로 가지 않으며, 나머지 줄은 아이디를 누르면 상세로 간다. 여러 쪽이면 페이지 탭.
3. 검색(아이디 · 이름 · 휴대폰 번호) — "검색"을 누르면 그 검색어로 1쪽을 다시 불러온다. 결과가 없으면 "검색한 업체 관리자가 없습니다."
4. "업체 관리자 등록"은 대화상자에 아이디 · 이름 · 휴대폰 번호(숫자만) · 성별 · 생년월일을 받는다. "등록"을 누르면 검사해 틀린 칸 옆에 오류를, 맞으면 등록(큐)을 보낸다.
5. 끝나서 회원 ID 를 받으면 그 상세로 가고(업체코드 · 아이디 · 임시 비밀번호가 그 휴대폰으로 문자), 결과 없이 끝나면 대화상자를 닫고 1쪽을 다시 불러온다. 아이디 · 휴대폰이 업체 안에서 겹치면 받은 문구를 칸 옆에.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `keyword` | | 검색어(100자) — 아이디 · 이름 · 휴대폰 부분 일치 |
| `login_id` | ✓ | 아이디(영문 · 숫자 · _ 4 ~ 30자, 업체 안에서 겹치지 않게) |
| `name` | ✓ | 이름(50자) |
| `phone` | ✓ | 휴대폰 번호(숫자만 — 01X 로 시작 10 ~ 11자리, 업체 안에서 겹치지 않게) |
| `gender` | ✓ | 성별(M · F) |
| `birth` | ✓ | 생년월일(YYYY-MM-DD) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 관리자를 등록한다 | 등록(큐) 1번(아이디 · 이름 · 숫자만 휴대폰 · 성별 · 생년월일) → 받은 회원 상세 주소로 이동 | ✓ 정상 |
| 아이디를 3자로 등록한다 | 칸 옆 "아이디는 영문 · 숫자 · _ 4~30자로 입력해주세요.", 등록 0번 | ✓ 검증 실패 |
| 업체 관리자 계정으로 연다 | 안내만, 목록 0번 | ✓ 정상 |
| 계정 쿠키를 아직 읽는 중이다 | 안내도 목록도 그리지 않고, 목록 0번 | ✓ 정상 |
| 이미 쓰는 아이디 · 휴대폰이다 | 받은 문구를 그 칸 옆에 | — (공통 실패 처리) |
| 검색한다 | 그 검색어로 1쪽 다시 | — (조회를 부르기만) |

## 2. 업체 관리자 상세 — `PAGE /manager/staff/[user_id]`

**동작 흐름**

1. 업체 총관리자가 아니면 목록과 같은 안내만 보이고 상세를 부르지 않는다. 업체 총관리자면 상세를 불러온다 — 못 읽으면 "업체 관리자를 불러오지 못했어요" 와 목록으로 가기.
2. 머리에 "업체 관리자 › 아이디", 이름 · 권한 배지 · 상태 배지(정상 · 정지) · 비밀번호 변경 필요 배지(임시 비밀번호 그대로면).
3. 계정 정보 카드 — 아이디 · 등록일 · 수정일은 읽기만, 이름 · 휴대폰 번호(숫자만) · 성별 · 생년월일을 고친다. "저장"을 누르면 검사해 틀린 칸 옆에 오류를, 맞으면 수정(큐 — 네 칸 통째로)을 보낸다.
4. 저장이 끝나면 상세를 다시 불러온다. 휴대폰이 업체 안에서 겹치면 받은 문구를 칸 옆에.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `user_id` | ✓ | 주소의 회원 ID |
| `name` · `phone` · `gender` · `birth` | ✓ | 등록과 같다 — 아이디는 바꾸지 않는다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 이름 · 휴대폰을 고쳐 저장한다 | 수정(큐) 1번(그 회원 — 이름 · 숫자만 휴대폰 · 성별 · 생년월일) → 상세 다시 | ✓ 정상 |
| 휴대폰을 7자리로 저장한다 | 칸 옆 "휴대폰 번호를 숫자만 정확히 입력해주세요.", 수정 0번 | ✓ 검증 실패 |
| 상세를 못 읽었다(없는 회원 · 연결 안 됨) | 안내 · 목록으로 | — (공통 빈 안내) |

## 3. 계정 관리 — `PAGE /manager/staff/[user_id]`

**동작 흐름**

1. 계정 관리 카드 — 비밀번호 초기화(임시 비밀번호를 그 휴대폰으로 보낸다는 안내), 정지(정지 사유 선택 · 255자 — 로그인할 때 보인다) 또는 정지된 계정이면 "정지 · 정지 사유" 와 정지 해제, 삭제(탈퇴 처리 — 같은 아이디 · 휴대폰으로 다시 등록할 수 있다는 안내).
2. 비밀번호 초기화 · 정지 · 삭제는 모두 확인 창을 한 번 거친다("○○ 계정의 비밀번호를 초기화할까요? 임시 비밀번호가 문자로 갑니다." · "○○ 계정을 정지할까요? 바로 로그인이 막힙니다." · "○○ 계정을 삭제할까요?"). 정지 해제는 확인 없이 바로.
3. 확인하면 비밀번호 초기화(큐) · 상태(큐 — 정지는 BLOCK + 사유, 해제는 ACTIVE) · 삭제(큐)를 보낸다.
4. 초기화가 끝나면 "임시 비밀번호를 보냈습니다." 안내, 정지 · 해제가 끝나면 상세를 다시 불러온다(초기화도 — 비밀번호 변경 필요 배지). 삭제가 끝나면 목록으로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `state_id` | ✓ | 바꿀 상태(BLOCK 정지 · ACTIVE 해제) |
| `block_comment` | | 정지 사유(255자) — 정지할 때만 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 정지 사유를 넣고 정지한다 | 확인 뒤 상태(큐) 1번(그 회원 — BLOCK · 사유) → 상세 다시 | ✓ 정상 |
| 비밀번호를 초기화한다 | 확인 뒤 초기화(큐) 1번(그 회원) → "임시 비밀번호를 보냈습니다." → 상세 다시 | ✓ 정상 |
| 계정을 지운다 | 확인 뒤 삭제(큐) 1번(그 회원) → 목록 주소로 이동 | ✓ 정상 |
| 정지를 해제한다 | 상태(큐 — ACTIVE, 사유 없이) → 상세 다시 | — (정지와 같은 흐름) |
| 확인 창에서 취소한다 | 아무것도 보내지 않는다 | — (공통 확인 창) |
