# 업체 콘솔 — 콘솔 틀 · 매니저 로그인 · 대시보드

## 한눈에

- **무엇을** 업체 관리자가 자기 업체 로그인 주소(`/manager/<업체코드>/login`)로 로그인하고, 아이디 찾기 · 비밀번호 초기화 · 비밀번호 변경을 하며, 왼쪽 메뉴 · 상단 바가 있는 콘솔에서 내 업체 통계(대시보드)를 본다.
- **왜** 업체 콘솔(`/manager`)에 들어갈 길이 없고, 앞으로 만들 업체 화면(예약 현황 · 호실 · 객실 그룹 · 상품 · 내 업체 · 업체 관리자)이 들어갈 틀이 없다.
- **범위 밖** 메뉴 중 대시보드 밖의 화면(Phase 11 ~ 14 — 그 전에는 눌러도 없는 화면), 관리자 콘솔 로그인(Phase 15 — 같은 콘솔 틀을 쓴다), 기기 알림 토큰(`device_os` · `device_token` — 웹은 보내지 않는다).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 콘솔 틀 | 왼쪽 메뉴(권한별) · 상단 바(업체 · 계정 · 비밀번호 변경 · 로그아웃) | 8건 |
| 2. 업체 로그인 | 주소의 업체코드 + 아이디 · 비밀번호로 로그인 | 3건 |
| 3. 로그인 처리 | Next 서버가 백엔드 로그인 → 토큰 · 계정 · 업체코드 쿠키 | 2건 |
| 4. 아이디 찾기 | 휴대폰 인증번호로 이 업체의 내 아이디 찾기 | 1건 |
| 5. 비밀번호 초기화 | 아이디 · 휴대폰 인증 → 임시 비밀번호 문자 | 0건 |
| 6. 업체 로그인 주소 안내 | 기억한 업체 로그인으로 보내거나 업체코드 붙여 넣기 | 4건 |
| 7. 비밀번호 변경 | 현재 · 새 비밀번호(임시 비밀번호로 로그인했으면 바로 이 화면) | 2건 |
| 8. 대시보드 | 기간 · 결제 환경별 합계 카드 · 월별 그래프 · 표 | 4건 |

## 1. 콘솔 틀 — `PAGE /manager/…`

**동작 흐름**

1. 로그인 뒤 업체 화면(`/manager/…`)은 모두 이 틀 안에 그린다. 로그인하지 않았으면 업체 로그인 주소 안내(6)를 거쳐 기억한 업체 로그인 화면으로 보낸다 — 돌아올 주소를 들고.
2. 들어오면 내 업체 상세(업체 이름 · 업체코드 · 영업 상태)와 로그인 때 기억한 계정(아이디 · 권한)을 읽는다. 내 업체 상세는 틀 안 화면(대시보드 · 내 업체 설정)과 나눠 쓴다.
3. 상단 바에 업체 이름 · "업체코드 3f9a2c7e…"(앞 8자) · 아이디 · 권한 배지(업체 총관리자 / 업체 관리자) · "비밀번호 변경" · "로그아웃"을 보여 준다.
4. 왼쪽 메뉴는 대시보드 · 예약 현황 · 호실 · 객실 그룹 · 상품 설정 · 내 업체 설정 · 업체 관리자 — 업체 관리자는 업체 총관리자에게만 보이고, 지금 화면의 메뉴를 강조한다. 화면이 좁으면 메뉴가 본문 위로 쌓인다.
5. 로그아웃하면 매니저 토큰 · 계정 쿠키를 지우고(업체코드는 남긴다) 업체 로그인 주소 안내를 새로 열어 기억한 업체 로그인 화면으로 간다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| (없음) | | 업체 · 계정은 토큰과 로그인 때 기억한 쿠키로 안다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 총관리자가 들어와 로그아웃한다 | 상단 바(업체 이름 · 줄인 업체코드 · 아이디 · 배지) · 메뉴 7개 → 쿠키 삭제 1번 → 업체 로그인 주소 안내를 새로 연다 | ✓ 정상 |
| 로그인하지 않았다 | 업체 로그인 주소 안내 → 기억한 업체 로그인(돌아올 주소) | — (공통 로그인 가드 + 6의 규칙) |
| 계정 쿠키가 없다(쿠키를 지웠다) | 아이디 · 배지 없이, 업체 관리자 메뉴 숨김 — 다시 로그인하면 돌아온다 | — (권한별 메뉴 규칙) |
| 내 업체 상세를 못 읽는다 | 업체 이름 자리를 비우고 실패 안내 | — (공통 실패 처리) |
| 아직 없는 화면 메뉴를 누른다 | 없는 화면(Phase 11 ~ 14 에서 생긴다) | — (범위 밖) |

**계산 규칙 — 권한별 메뉴** `visibleMenu`

검증: 업체 관리자 메뉴는 업체 총관리자에게만 보이고, 나머지 메뉴는 누구에게나 보인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 업체 총관리자는 업체 관리자 메뉴까지 모두 본다 | `'HEAD_MANAGER'` | 대시보드 ~ 업체 관리자 7개 |
| 업체 관리자이거나 권한을 모르면 업체 관리자 메뉴가 없다 | `'MANAGER'` · `null` | 업체 관리자를 뺀 6개 |

**계산 규칙 — 지금 메뉴** `activeMenuHref`

검증: 주소가 메뉴 주소와 같거나 그 아래면 그 메뉴를 강조하고, 대시보드는 첫 화면에서만 강조한다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 메뉴 아래 주소도 그 메뉴로 본다 | `'/manager/room-groups/abc/'` | 객실 그룹 |
| 이름 앞부분만 같은 다른 메뉴는 고르지 않는다 | `'/manager/rooms/'` | 호실(객실 그룹 아님) |
| 대시보드는 첫 화면에서만 강조한다 | `'/manager/reservations/'` | 예약 현황(대시보드 아님) |

**계산 규칙 — 업체코드 줄임** `shortStoreCode`

검증: 긴 업체코드는 앞 8자만 보이고 뒤를 줄임표로 줄인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 32자 업체코드는 앞 8자에 줄임표를 붙인다 | `'3f9a2c7e5b1d4a8e9c0f6b2d7e4a1c21'` | `'3f9a2c7e…'` |
| 8자 이하면 그대로 보인다 | `'3f9a2c7e'` | `'3f9a2c7e'` |

## 2. 업체 로그인 — `PAGE /manager/[store_code]/login`

**동작 흐름**

1. 메뉴 없이 바탕 가운데 카드 — "업체 관리자 로그인" 제목(로그인 전에는 업체 이름을 읽는 API 가 없어 업체 이름은 띄우지 않는다), 아이디 · 비밀번호, "로그인", 아이디 찾기 · 비밀번호 초기화 링크(같은 업체코드 주소).
2. 이미 매니저로 로그인했으면 돌아갈 주소로 보낸다.
3. "로그인"을 누르면 주소의 업체코드 · 아이디 · 비밀번호를 검사해 틀린 칸 옆에 오류를 보이고, 맞으면 로그인 처리(3)를 부른다.
4. 되면 임시 비밀번호로 로그인했을 때(비밀번호 변경 필요)는 비밀번호 변경(7)으로, 아니면 돌아갈 주소(없으면 대시보드)로 간다.
5. 안 되면 제목 아래 위험 띠 — 틀린 정보는 "잘못된 로그인 정보입니다."(아이디 · 비밀번호 · 업체코드 중 무엇이 틀렸는지 가르지 않는다), 정지 계정은 받은 문구와 "정지 사유: …".

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_code` | ✓ | 주소의 업체코드(32자 영문 소문자 · 숫자) — 화면에서 받지 않는다 |
| `login_id` | ✓ | 아이디(30자까지) |
| `login_pw` | ✓ | 비밀번호(20자까지) |
| `return_url` | | 로그인 뒤 돌아갈 주소(같은 사이트만) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 맞는 아이디 · 비밀번호로 로그인한다 | 로그인 처리 1번(주소의 업체코드 그대로) → 돌아갈 주소 | ✓ 정상 |
| 임시 비밀번호로 로그인한다 | 비밀번호 변경 화면(임시 비밀번호 안내 띠) | ✓ 정상 |
| 아이디를 비우고 누른다 | 칸 옆 "아이디를 입력해주세요.", 로그인 처리 0번 | ✓ 검증 실패 |
| 정보가 틀렸다 · 정지 계정이다 | 위험 띠 — 받은 문구(정지면 "정지 사유: …" 줄 더) | — (로그인 처리가 문구를 그대로 넘긴다 — 3에서 확인) |
| 이미 로그인했다 | 돌아갈 주소로 | — (이용자 로그인과 같은 처리) |

## 3. 로그인 처리 — `POST /api/manager/login`

**동작 흐름**

1. 같은 사이트의 JSON 요청만 받는다(다른 사이트 form 이 로그인 쿠키를 심는 것 막기).
2. Next 서버가 백엔드 매니저 로그인(동기)을 부른다 — 재발급도 Next 서버가 부르므로 로그인 IP 와 재발급 IP 가 같다.
3. 되면 매니저 토큰 쿠키 2개, 계정 쿠키(아이디 · 권한 — 토큰과 같이 지운다), 업체코드 쿠키(1년 — 로그아웃해도 남는다)를 쓰고 비밀번호 변경 필요 여부를 돌려준다.
4. 안 되면 백엔드 실패 문구 · 칸 오류 · 정지 사유를 그대로 돌려주고 쿠키는 쓰지 않는다. 네트워크 · 백엔드 5xx 는 "잠시 뒤 다시"로 돌려준다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_code` · `login_id` · `login_pw` | ✓ | 화면이 검사한 값 그대로(서버도 같은 DTO 로 다시 검사) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 백엔드 로그인이 된다 | 백엔드 로그인 1번 → 토큰 · 계정 · 업체코드 쿠키 → 비밀번호 변경 필요 여부 | ✓ 정상 |
| 백엔드가 404 · 403 으로 거절한다 | 받은 문구 · 정지 사유 그대로, 쿠키 0개 | ✓ 실패 |
| 다른 사이트 요청 · JSON 아님 | 실패, 백엔드 0번 | — (공통 같은 사이트 검사 — 가입 route 와 같다) |
| 네트워크 · 백엔드 5xx | 실패 + 다시 시도 안내 | — (가입 route 와 같은 처리) |

## 4. 아이디 찾기 — `PAGE /manager/[store_code]/find-login-id`

**동작 흐름**

1. 메뉴 없는 가운데 카드 — "아이디 찾기", 계정에 등록된 휴대폰 번호로 인증번호를 받는다는 안내, 1 · 2단계 표시.
2. 휴대폰 번호를 넣고 "인증번호 받기"를 누르면 주소의 업체코드와 함께 인증번호 발송(큐)을 부른다. 5분 남은 시간을 보여 주고, 다 되면 다시 받기만 켠다.
3. 6자리를 넣고 "확인"하면 인증번호 확인(큐) → 찾은 아이디 · 등록일과 "로그인" · "비밀번호 초기화" 버튼(같은 업체코드 주소)을 보여 준다.
4. 결과 없이 끝나면(늦어짐) 늦어짐 안내.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `phone` | ✓ | 계정에 등록된 휴대폰 번호(숫자만) |
| `code` | ✓ | 인증번호 6자리 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 번호로 인증번호를 받아 확인한다 | 발송 1번(주소의 업체코드 · 번호) → 확인 1번 → 아이디 · 등록일 · 로그인 / 비밀번호 초기화 링크 | ✓ 정상 |
| 번호 · 인증번호 모양이 틀렸다 | 칸 옆 DTO 문구, API 0번 | — (이용자 아이디 찾기와 같은 인증번호 부품 · DTO 검증) |
| 그 업체에 그 번호 계정이 없다 · 인증번호가 틀렸다 | 받은 문구 팝업 | — (공통 실패 처리) |

## 5. 비밀번호 초기화 — `PAGE /manager/[store_code]/password-reset`

**동작 흐름**

1. 메뉴 없는 가운데 카드 — "비밀번호 초기화", 아이디와 등록된 휴대폰 번호가 맞으면 인증번호를 보내고 인증이 끝나면 임시 비밀번호가 문자로 간다는 안내.
2. 아이디 · 휴대폰 번호로 "인증번호 받기"(큐 — 주소의 업체코드와 함께), 6자리로 "확인"(큐).
3. 확인되면 "임시 비밀번호를 문자로 보냈습니다." · 임시 비밀번호(영문 + 숫자 10자리)로 로그인하면 비밀번호 변경으로 간다는 안내 · "로그인" 버튼.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `login_id` | ✓ | 아이디(30자까지) |
| `phone` | ✓ | 계정에 등록된 휴대폰 번호(숫자만) |
| `code` | ✓ | 인증번호 6자리 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 아이디 · 번호로 인증해 초기화한다 | 발송 1번(업체코드 · 아이디 · 번호) → 확인 1번 → 임시 비밀번호 안내 | — (아이디 찾기와 같은 인증 흐름에 아이디 칸만 더) |
| 아이디를 비웠다 | 칸 옆 "아이디를 입력해주세요.", 발송 0번 | — (아이디 찾기 · 로그인과 같은 DTO 검증) |
| 아이디 · 번호가 맞는 계정이 없다 | 받은 문구 팝업 | — (공통 실패 처리) |

## 6. 업체 로그인 주소 안내 — `PAGE /manager/login`

**동작 흐름**

1. 업체코드 없이 들어왔거나 로그인이 필요해 보내진 화면이다. 브라우저에 기억한 업체코드(업체코드 쿠키)가 있으면 이 화면을 보이지 않고 바로 그 업체 로그인 화면으로 보낸다 — 돌아갈 주소를 들고.
2. 없으면 "업체 로그인 주소로 접속해 주세요" 안내와 로그인 주소 모양, 업체코드 칸 하나를 보여 준다.
3. 붙여 넣은 업체코드(앞뒤 공백은 지운다)가 32자 영문 소문자 · 숫자가 아니면 칸 아래 "업체코드가 올바르지 않습니다."를 보이고, 맞으면 그 업체 로그인 화면으로 간다 — API 는 부르지 않는다(없는 업체코드면 로그인할 때 "잘못된 로그인 정보입니다.").

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_code` | ✓ | 로그인 주소 안의 32자 |
| `return_url` | | 로그인 뒤 돌아갈 주소 — 업체 로그인 화면으로 넘긴다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체코드 모양이 틀렸다 | 칸 아래 "업체코드가 올바르지 않습니다.", 이동 없음 | ✓ 검증 실패 |
| 맞는 업체코드를 붙여 넣는다 | 그 업체 로그인 화면(돌아갈 주소를 들고) | — (아래 업체 로그인 주소 규칙) |
| 기억한 업체코드가 있다 | 이 화면 없이 그 업체 로그인 화면으로 | — (아래 업체 로그인 주소 규칙) |

**계산 규칙 — 업체 로그인 주소** `managerLoginPath`

검증: 업체코드 모양이 맞을 때만 그 업체 로그인 주소를 만들고, 같은 사이트의 돌아갈 주소만 붙인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 업체코드로 그 업체 로그인 주소를 만든다 | `('3f9a…c21', null)` | `'/manager/3f9a…c21/login/'` |
| 같은 사이트의 돌아갈 주소는 붙인다 | `('3f9a…c21', '/manager/rooms/')` | `'/manager/3f9a…c21/login/?return_url=%2Fmanager%2Frooms%2F'` |
| 업체코드 모양이 아니면 만들지 않는다 | `('not-a-store-code', null)` | `null` |

## 7. 비밀번호 변경 — `PAGE /manager/password`

**동작 흐름**

1. 매니저 로그인이 필요하다(아니면 1의 로그인 가드와 같다). 메뉴 없는 가운데 카드에 기억한 아이디 · 권한 배지를 보여 준다.
2. 임시 비밀번호로 로그인해서 왔으면 "임시 비밀번호로 로그인했습니다. 새 비밀번호로 바꿔 주세요." 띠를 보인다. 상단 바 "비밀번호 변경"으로 오면 띠가 없다.
3. 현재 · 새 비밀번호를 검사해 틀린 칸 옆에 오류를 보이고, 맞으면 비밀번호 변경(큐)을 부른다.
4. 되면 "비밀번호를 바꿨습니다." 안내 뒤 대시보드로 간다. "취소"는 대시보드로.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `current_password` | ✓ | 현재 비밀번호(임시 비밀번호로 로그인했다면 문자로 받은 것) |
| `new_password` | ✓ | 8 ~ 20자, 영문과 숫자를 반드시 포함(특수문자는 !@#$%^&* 만) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 맞는 현재 비밀번호와 규칙에 맞는 새 비밀번호로 바꾼다 | 변경(큐) 1번 → "비밀번호를 바꿨습니다." → 대시보드 | ✓ 정상 |
| 새 비밀번호에 숫자가 없다 | 칸 옆 DTO 문구, 변경 0번 | ✓ 검증 실패 |
| 현재 비밀번호가 틀렸다 | 받은 문구(칸 오류면 칸 옆) | — (공통 실패 처리) |
| 로그인하지 않았다 | 업체 로그인 주소 안내 → 기억한 업체 로그인 | — (공통 로그인 가드) |

## 8. 대시보드 — `PAGE /manager`

**동작 흐름**

1. 콘솔 틀 안의 첫 화면. 들어오면 기간을 비우고(최근 3개월) 실결제로 내 업체 통계를 불러오고, 받은 기간을 시작 달 · 끝 달 칸에 채운다.
2. 시작 달 · 끝 달 · 결제 환경(실결제 · 테스트 결제)을 바꾸고 "조회"를 누르면 그 값으로 다시 불러온다. 기간을 비우면 최근 3개월이고 최대 12개월이다(넘으면 백엔드 안내).
3. 합계 카드 5개(이용자 수 · 이용 건수 · 결제액 · 환불액 · 수익), 월별 결제액 · 환불액 막대그래프(막대 위 값과 눈금은 "만" 글자), 월별 표(항목 5줄 × 달 + 합계)를 보여 준다.
4. 업체가 영업중지면 제목 아래 "영업중지된 업체입니다. 사유: …" 위험 띠를 보인다(콘솔 틀이 읽은 내 업체 상세).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `start_month` | | 시작 달(YYYY-MM) — 비우면 끝 달 − 2개월 |
| `end_month` | | 끝 달(YYYY-MM) — 비우면 이번 달 |
| `environment` | | 결제 환경 LIVE(실결제 · 기본) · TEST(테스트 결제) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 들어온다 | 통계 1번(기간 비움 · 실결제) → 받은 기간을 칸에 · 합계 카드 · 월별 표(합계 칸) | ✓ 정상 |
| 기간 · 결제 환경을 바꿔 조회한다 | 그 값으로 통계를 다시 | — (같은 조회에 값만 바뀐다) |
| 끝 달이 시작 달보다 앞이다 · 12개월을 넘는다 | 받은 문구 팝업 | — (공통 실패 처리) |
| 영업중지 업체다 | 위험 띠 + 정지 사유 | — (그리기만) |

**계산 규칙 — 금액 "만" 글자** `formatManwon`

검증: 1만 원 이상은 만 단위로 반올림해 "만"을 붙이고, 1만 원 미만은 쉼표로 나눈 숫자 그대로 보인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 만 단위로 줄여 "만"을 붙인다 | `3420000` | `'342만'` |
| 만 아래 자리는 반올림한다 | `238000` | `'24만'` |
| 1만 원 미만은 숫자 그대로 보인다 | `5000` | `'5,000'` |
