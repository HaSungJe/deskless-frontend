# 상품 · 객실 — 상품 설정 · 객실 그룹 · 호실

## 한눈에

- **무엇을** 업체 관리자가 콘솔에서 상품(시간 이용 · 1박 · 연박)의 판매 · 요일 · 시간 · 연장을 정하고, 객실 그룹(기본 정보 · 사진 · 그룹 상품 요금 · 기간 가격)과 호실(등록 · 수정 · 상태 · 문 바로 열기 · 삭제)을 관리한다.
- **왜** 콘솔 메뉴 "호실 · 객실 그룹 · 상품 설정"의 화면이 없어, 업체가 팔 객실과 요금을 스스로 만들 길이 없다.
- **범위 밖** 예약 현황 · 호실 이동(M3 — Phase 13), 업체 영업시간 · 규정(M7 — Phase 11), 업체 관리자 관리(M8 — Phase 14).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 상품 설정 | 상품 카드 3개 — 판매 · 요일 · 시간 · 박수 · 연장, 카드마다 저장 | 4건 |
| 2. 객실 그룹 목록 | 그룹명 검색 · 그룹 카드 · 그룹 등록 | 2건 |
| 3. 객실 그룹 상세 | 기본 정보 · 사진 · 그룹 상품(판매 · 기본 요금) · 그룹 삭제 | 4건 |
| 4. 상품별 기간 가격 | 상품을 골라 기간 가격 목록 · 추가 · 수정 · 삭제 | 2건 |
| 5. 호실 | 층 · 그룹 거르기 · 호실 표 · 등록 · 수정 · 상태 · 문 바로 열기 · 삭제 | 11건 |

## 1. 상품 설정 — `PAGE /manager/plans`

**동작 흐름**

1. 화면을 열면 업체 상품 설정 3개(시간 이용 · 1박 · 연박)를 불러와 카드 3개로 보인다. 위에 "연장 설정은 이용자가 연장할 때의 지금 설정을 따릅니다. 판매하지 않는 상품은 그룹 상품을 켜도 팔리지 않습니다." 안내 띠.
2. 카드마다 판매 스위치 · 판매 요일(일 ~ 토 칩 — 고른 요일을 "매일" · "일 ~ 목" 처럼 옆에 보인다) · 연장 가능 스위치 · 최대 연장 횟수(1 ~ 10 — 연장 불가여도 값은 남는다)가 있고, 시간 이용은 이용 시간(1 ~ 24시간), 1박은 입실 · 퇴실 시각(퇴실은 늘 다음 날), 연박은 입실 · 퇴실 시각과 최소 · 최대 박수(1 ~ 180)가 더 있다.
3. 카드의 "저장"을 누르면 그 상품 종류에 맞는 칸만 모아 검사하고, 틀리면 그 카드의 칸 옆에 오류를, 맞으면 그 상품 설정을 저장(큐)한다.
4. 저장이 끝나면 버튼 옆에 "저장했습니다."를 보이고 3개를 다시 불러온다. 입실 · 퇴실이 같거나 최소 박수가 최대보다 크면 받은 문구를 그 카드의 칸 옆에 보인다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `room_plan_type_id` | ✓ | 상품 종류(HOURLY · NIGHT · LONG) — 카드 |
| `is_used` | ✓ | 판매(0 · 1) |
| `days_of_week` | ✓ | 판매 요일 비트 합(일 1 ~ 토 64, 매일 127) — 하나 이상 |
| `is_extendable` · `max_extensions` | ✓ | 연장 가능(0 · 1) · 최대 연장 횟수(1 ~ 10) |
| `usage_hours` | 시간 이용 | 이용 시간(1 ~ 24) |
| `check_in_time` · `check_out_time` | 1박 · 연박 | 입실 · 퇴실 시각(HH:mm — 서로 달라야 한다) |
| `min_nights` · `max_nights` | 연박 | 최소 · 최대 박수(1 ~ 180, 최소 ≤ 최대) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 1박 카드를 고쳐 저장한다 | 저장(큐) 1번(1박 — 판매 · 요일 비트 합 · 입실 · 퇴실 · 연장 · 최대 연장) → "저장했습니다." → 다시 불러오기 | — (보낼 값은 아래 규칙이 확인, 저장 뒤 다시 부르기는 공통 흐름) |
| 판매 요일을 하나도 고르지 않고 저장한다 | 그 카드 칸 옆 "예약 가능 요일은 1 ~ 127 사이로 입력해주세요.", 저장 0번 | ✓ 검증 실패 |
| 입실 · 퇴실이 같다 · 최소 박수가 최대보다 크다 | 받은 문구를 그 카드 칸 옆에 | — (공통 실패 처리) |

**계산 규칙 — 상품 설정 보낼 값** `toPlanUpdateDto`

검증: 판매 · 요일 · 연장은 늘 보내고, 시간 이용은 이용 시간만, 1박은 입실 · 퇴실 시각만, 연박은 시각과 최소 · 최대 박수까지 보낸다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 시간 이용은 이용 시간만 보낸다 | 시간 이용 카드 — 3시간, 시각 칸에 값이 남아 있음 | 공통 칸 + 이용 시간 3, 시각 · 박수 없음 |
| 1박은 입실 · 퇴실 시각만 보낸다 | 1박 카드 — 15:00 입실 · 11:00 퇴실 | 공통 칸 + 입실 15:00 · 퇴실 11:00, 이용 시간 · 박수 없음 |
| 연박은 시각과 최소 · 최대 박수까지 보낸다 | 연박 카드 — 15:00 · 11:00, 2 ~ 30박 | 공통 칸 + 시각 + 최소 2 · 최대 30 |

## 2. 객실 그룹 목록 — `PAGE /manager/room-groups`

**동작 흐름**

1. 화면을 열면 객실 그룹을 한 쪽에 20개씩, 등록일 최신순으로 불러와 카드로 보인다(대표 사진 — 없으면 "사진 없음" 자리 · 그룹명 · "호실 n개 · 등록 YYYY-MM-DD"). 카드를 누르면 그 그룹 상세로 간다. 여러 쪽이면 페이지 탭.
2. 그룹명 검색 — "검색"을 누르면 그 검색어로 1쪽을 다시 불러온다. 결과가 없으면 "검색한 그룹이 없습니다.", 그룹이 하나도 없으면 "아직 객실 그룹이 없습니다. 그룹 등록으로 첫 그룹을 만드세요." 와 그룹 등록 버튼.
3. "그룹 등록"을 누르면 대화상자에 상세의 기본 정보와 같은 칸(그룹명 · 방 개수 · 설명 · 샤워실 · TV · PC)을 빈 값(방 1개 · 편의시설 모두 있음)으로 연다.
4. "등록"을 누르면 검사해 틀린 칸 옆에 오류를, 맞으면 그룹 등록(큐)을 보낸다. 끝나서 그룹 ID 를 받으면 그 그룹 상세로 가고, 결과 없이 끝나면 대화상자를 닫고 목록을 다시 불러온다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `keyword` | | 그룹명 검색어(100자) |
| `room_group_name` | ✓ | 그룹명(100자 — 업체 안에서 겹치지 않게) |
| `description` | | 설명(2,000자) — 비우면 없앤다 |
| `room_group_detail` | | 방 개수(1 ~ 20) · 샤워실 · TV · PC(0 · 1) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 그룹을 등록한다 | 등록(큐) 1번(그룹명 · 설명 · 방 개수 · 편의시설) → 받은 그룹 상세 주소로 이동 | ✓ 정상 |
| 그룹명을 비우고 등록한다 | 칸 옆 "그룹명을 입력해주세요.", 등록 0번 | ✓ 검증 실패 |
| 이미 있는 그룹명이다 | 받은 문구를 그룹명 칸 옆에 | — (공통 실패 처리) |
| 검색한다 | 그 검색어로 1쪽 다시 불러오기 | — (조회를 부르기만) |

## 3. 객실 그룹 상세 — `PAGE /manager/room-groups/[room_group_id]`

**동작 흐름**

1. 화면을 열면 그룹 상세를 불러온다. 머리에 "객실 그룹 › 그룹명", 그룹명, "호실 3개(203호 · 301호 · 302호) · 등록 YYYY-MM-DD · 수정 YYYY-MM-DD HH:mm"(호실이 없으면 "호실 0개"), "그룹 삭제" 버튼. 못 읽으면 "객실 그룹을 불러오지 못했어요" 와 목록으로 가기.
2. 기본 정보 카드 — 그룹명 · 방 개수 · 설명(글자 수) · 편의시설(샤워실 · TV · PC 스위치). "기본 정보 저장"을 누르면 검사해 틀린 칸 옆에 오류를, 맞으면 그룹 수정(큐 — 편의시설은 통째로)을 보낸다.
3. 사진 카드 — 사진(5장까지 · 첫 번째가 대표 · 몇 장인지 3 / 5)을 올리기(업로드 주소 → PUT → 등록 큐) · 끌어서 순서(사진 ID 전부 — 큐) · 확인 뒤 삭제(큐)한다.
4. 그룹 상품 카드 — "업체 상품 설정에서 판매하지 않는 상품은 그룹 상품을 켜도 팔리지 않습니다." 안내와 "업체 상품 설정으로" 링크, 상품마다 판매 스위치 · 기본 요금 · 기간 가격 개수("2개" — 누르면 아래 기간 가격 절이 그 상품으로) · 저장. 줄의 "저장"은 그 상품의 판매 · 기본 요금을 저장(큐)한다. 판매인데 요금이 0 이면 받은 문구를 그 줄 요금 칸 옆에.
5. 2 ~ 4 가 끝나면 그룹 상세를 다시 불러온다.
6. "그룹 삭제"는 확인 창("○○ 그룹을 삭제할까요? 그룹의 호실 · 사진도 함께 지워집니다.") 뒤 그룹 삭제(큐)를 보내고 객실 그룹 목록으로 간다. 예약이 있으면 받은 문구("예약이 있는 객실 그룹은 지울 수 없습니다.").

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `room_group_id` | ✓ | 주소의 그룹 ID |
| `room_group_name` · `description` · `room_group_detail` | ✓ · · | 그룹 등록과 같다 |
| 파일 · `room_group_image_ids` | | 그룹 사진(JPG · PNG, 5장) · 순서(사진 ID 전부) |
| `room_plan_type_id` · `is_used` · `price` | ✓ | 그룹 상품 줄 — 판매(0 · 1) · 기본 요금(0 ~ 10,000,000원, 판매면 1원 이상) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 기본 정보를 고쳐 저장한다 | 수정(큐) 1번(그룹명 · 설명 · 방 개수 · 샤워실 · TV · PC 0 · 1) → 상세 다시 | ✓ 정상 |
| 방 개수를 0 으로 저장한다 | 칸 옆 "방 개수는 1 ~ 20 사이로 입력해주세요.", 수정 0번 | ✓ 검증 실패 |
| 1박을 판매로 켜고 요금을 넣어 저장한다 | 그룹 상품 수정(큐) 1번(1박 — 판매 1 · 요금) → 상세 다시 | ✓ 정상 |
| 그룹을 지운다 | 확인 뒤 삭제(큐) 1번 → 객실 그룹 목록으로 이동 | ✓ 정상 |
| 사진을 올린다 · 순서를 바꾼다 · 지운다 | 내 업체 사진과 같은 흐름 → 상세 다시 | — (내 업체 사진 탭과 같은 흐름) |
| 판매인데 요금이 0 이다 · 예약이 있어 지울 수 없다 | 받은 문구(그 줄 요금 칸 옆 · 오류 팝업) | — (공통 실패 처리) |

## 4. 상품별 기간 가격 — `PAGE /manager/room-groups/[room_group_id]`

**동작 흐름**

1. 그룹 상세 아래 "상품별 기간 가격" 절 — 상품(시간 이용 · 1박 · 연박)을 고르면(처음은 시간 이용) 그 상품의 기간 가격을 한 쪽에 20개씩, 시작 날짜 순으로 불러온다(기간 · 요금 · 메모 · 수정 · 삭제). 아래에 "시작 · 종료 날짜 모두 포함. 이 기간에는 기본 요금(1박 59,000원) 대신 이 요금으로 팝니다." 없으면 "기간 가격이 없습니다."
2. "기간 가격 추가"는 대화상자(제목 "기간 가격 추가 — 1박")에 시작 · 종료 날짜 · 요금 · 메모(선택 · 30자)를 받는다. 줄의 "수정"은 같은 대화상자를 그 값으로 채워 연다(제목 "기간 가격 수정 — 1박", "저장").
3. "추가" · "저장"을 누르면 검사해 틀린 칸 옆에 오류를, 맞으면 기간 가격 등록 · 수정(큐 — 통째로)을 보낸다. 날짜가 겹치거나 종료가 시작보다 빠르면 받은 문구를 칸 옆에.
4. 줄의 "삭제"는 확인 창 뒤 삭제(큐).
5. 추가 · 수정 · 삭제가 끝나면 대화상자를 닫고 그 상품의 목록과 그룹 상세(기간 가격 개수)를 다시 불러온다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `room_plan_type_id` | ✓ | 고른 상품 |
| `start_date` · `end_date` | ✓ | 시작 · 종료 날짜(YYYY-MM-DD, 둘 다 포함 — 종료 ≥ 시작) |
| `price` | ✓ | 이 기간의 요금(1 ~ 10,000,000원) |
| `memo` | | 메모(30자) — 비우면 없앤다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 1박 기간 가격을 추가한다 | 등록(큐) 1번(그룹 · 1박 — 시작 · 종료 날짜 · 요금 · 메모) → 대화상자 닫힘 → 1박 목록 · 상세 다시 | ✓ 정상 |
| 요금을 0 으로 추가한다 | 칸 옆 "기간 요금은 1 ~ 10,000,000원 사이로 입력해주세요.", 등록 0번 | ✓ 검증 실패 |
| 기간 가격을 고쳐 저장한다 · 지운다 | 수정(큐 — 그 기간) · 확인 뒤 삭제(큐) → 목록 · 상세 다시 | — (추가와 같은 흐름) |
| 다른 기간과 날짜가 겹친다 | 받은 문구를 시작 날짜 칸 옆에 | — (공통 실패 처리) |
| 다른 상품을 고른다 | 그 상품 1쪽 불러오기 | — (조회를 부르기만) |

## 5. 호실 — `PAGE /manager/rooms`

**동작 흐름**

1. 화면을 열면 호실을 한 쪽에 20개씩(층 · 호실명 순)과, 거르기 · 등록에 쓸 객실 그룹 전체를 불러온다. 거르기는 층(응답의 `floors` — "전체 · B1 · 2층 · 3층") · 객실 그룹(전체 · 그룹들) · "초기화"이고, 바꾸면 1쪽을 다시 불러온다.
2. 표 — 호실 · 층 · 객실 그룹 · 호실 상태 배지(응답의 상태명) · 마지막으로 연 시각(연 적 없으면 "-") · 작업(수정 · 상태 · 문 열기 · 삭제). 위에 "사용중지로 바꾸면 그 호실 예약자는 예약 끝 전까지 전액 환불 취소를 할 수 있습니다. 앞으로의 예약이 있는 호실은 삭제할 수 없습니다. 문 열기는 문 쪽 프로그램이 연결돼 있어야 합니다." 안내 띠.
3. "호실 등록"은 대화상자에 객실 그룹(고르기) · 호실명 · 층(-10 ~ 200, 지하는 음수)을, 줄의 "수정"은 같은 대화상자에 그룹은 읽기만("그룹은 바꾸지 않습니다. 잘못 등록했으면 지우고 다시 등록합니다.")으로 연다. 누르면 검사 뒤 등록 · 수정(큐).
4. 줄의 "상태"는 작은 대화상자("203호 · 지금 정비중")에 지금 상태로 고를 수 있는 버튼과 사용중지 안내를 보이고, 누르면 바로 상태 변경(큐).
5. 줄의 "문 열기"는 문 바로 열기(동기)를 부르고, 받은 시각으로 그 줄의 "마지막으로 연 시각"만 바꾼다(목록은 다시 부르지 않는다). 문 쪽 프로그램이 연결돼 있지 않으면(503) 받은 문구를 오류 팝업으로.
6. 줄의 "삭제"는 확인 창 뒤 삭제(큐). 3 · 4 · 6 이 끝나면 대화상자를 닫고 지금 쪽을 다시 불러온다. 호실명이 겹치면 받은 문구를 칸 옆에, 예약이 있어 지울 수 없으면 받은 문구를 오류 팝업으로.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `floor` · `room_group_id` | | 거르기 — 층(정수 글자) · 객실 그룹 ID, 없으면 전체 |
| `room_group_id` | 등록 ✓ | 객실 그룹(등록 때만 — 바꾸지 않는다) |
| `room_name` | ✓ | 호실명(50자 — 업체 안에서 겹치지 않게) |
| `floor` | ✓ | 층(-10 ~ 200 정수, B1 = -1) |
| `room_state_id` | ✓ | 바꿀 상태(AVAILABLE · DISABLED) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 층과 객실 그룹으로 거른다 | 호실 목록 1번 더(1쪽 · 층 글자 · 그룹 ID) | — (조회를 부르기만) |
| 호실을 등록한다 | 등록(큐) 1번(그룹 ID · 호실명 · 층 숫자) → 대화상자 닫힘 → 목록 다시 | ✓ 정상 |
| 층을 300 으로 등록한다 | 칸 옆 "층은 -10 ~ 200 사이로 입력해주세요.", 등록 0번 | ✓ 검증 실패 |
| 정비중 호실을 "정비 완료"로 바꾼다 | 상태 변경(큐) 1번(그 호실 — AVAILABLE) → 목록 다시 | — (고를 버튼은 아래 규칙이 확인, 부르기는 등록과 같은 흐름) |
| 문을 연다 | 문 바로 열기 1번(그 호실) → 그 줄 시각이 받은 시각으로, 목록은 다시 부르지 않음 | ✓ 정상 |
| 호실을 고쳐 저장한다 · 지운다 | 수정(큐 — 호실명 · 층) · 확인 뒤 삭제(큐) → 목록 다시 | — (등록 · 그룹 삭제와 같은 흐름) |
| 이미 있는 호실명이다 · 예약이 있어 지울 수 없다 · 문 쪽이 연결돼 있지 않다 | 받은 문구(칸 옆 · 오류 팝업) | — (공통 실패 처리) |

**계산 규칙 — 마지막으로 연 시각 글자** `formatOpenedAt`

검증: 백엔드의 한국 시각 글자를 시간대를 바꾸지 않고 "날짜 시각"으로 쓰고, 연 적이 없거나 모양이 틀리면 줄표로 둔다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 시각 글자를 날짜 시각으로 바꾼다 | `'20261119143005'` | `'2026-11-19 14:30'` |
| 연 적이 없으면 줄표 | `null` | `'-'` |
| 모양이 틀린 글자면 줄표 | `'2026-11-19'` | `'-'` |

**계산 규칙 — 층 이름** `floorLabel`

검증: 지상 층은 뒤에 "층"을 붙이고, 지하 층은 앞에 B 를 붙인다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 지상 층은 "층"을 붙인다 | `3` | `'3층'` |
| 지하 층은 B 를 붙인다 | `-1` | `'B1'` |

**계산 규칙 — 상태별 고를 수 있는 버튼** `roomStateActions`

검증: 정비중이면 정비 완료와 사용중지, 사용중지면 사용 재개, 그 밖의 상태면 사용중지만 고를 수 있다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 예약완료 호실은 사용중지만 고른다 | `'RESERVED'` | 사용중지(→ DISABLED) |
| 정비중 호실은 정비 완료와 사용중지를 고른다 | `'MAINTENANCE'` | 정비 완료(→ AVAILABLE) · 사용중지(→ DISABLED) |
| 사용중지 호실은 사용 재개만 고른다 | `'DISABLED'` | 사용 재개(→ AVAILABLE) |
