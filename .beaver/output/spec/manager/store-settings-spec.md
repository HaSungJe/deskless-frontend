# 내 업체 설정 — 기본 정보 · 사진 · 영업 규정

## 한눈에

- **무엇을** 업체 관리자가 콘솔의 "내 업체 설정"(`/manager/store`)에서 업체 정보를 보고, 소개 · 연락처 · 사진 · 영업시간 · 브레이크 · 영업중 · 정비시간 · 예약 · 환불 규정 · 일시 예약불가를 바꾸며, 업체 총관리자는 문 쪽 프로그램의 시크릿을 정한다.
- **왜** 콘솔 메뉴 "내 업체 설정"의 화면이 없어, 업체가 이용자 화면에 보일 정보와 예약 규칙을 스스로 바꿀 길이 없다.
- **범위 밖** 상호명 · 주소 · 위치 · 사업자 정보 수정(총관리자 — Phase 16), 사업자등록증 바꾸기 · 지우기(총관리자에게 요청), 호실 · 객실 그룹 · 상품(Phase 12).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 기본 정보 탭 | 업체코드 · 로그인 주소 복사 · 상태 · 사업자 정보 보기, 소개 · 연락처 저장 | 2건 |
| 2. 사진 탭 | 업체 사진 올리기 · 끌어서 순서 · 삭제, 사업자등록증 보기 | 2건 |
| 3. 영업시간 탭 | 24시간 · 요일별 휴무 · 여는 / 닫는 시각, 브레이크타임 — 통째로 저장 | 9건 |
| 4. 운영 규정 탭 | 영업중 · 정비시간 · 예약 · 환불 규정 | 5건 |
| 5. 일시 예약불가 탭 | 끝나지 않은 기간 목록 · 추가 · 삭제 | 4건 |
| 6. 문 연동 탭 | 시크릿 설정 여부 · 새 시크릿 — 업체 총관리자만 | 3건 |

## 1. 기본 정보 탭 — `PAGE /manager/store`

**동작 흐름**

1. 콘솔 틀이 읽은 내 업체 상세로 화면을 그린다 — 머리에 "내 업체 설정" · 업체 상태 배지(활성 · 영업중지) · 영업중 배지 · 마지막 수정 일시, 영업중지면 "영업중지된 업체입니다. 사유: …" 위험 띠. 아래에 탭 6개(지금 탭은 화면 상태 — 주소에 남기지 않는다, 들어오면 기본 정보).
2. 업체코드 · 업체 로그인 주소(`<프론트 주소>/manager/<업체코드>/login/`)와 "로그인 주소 복사", 상태 · 상호명 · 사업자등록번호 · 대표자명 · 주소 · 위치는 읽기만 한다.
3. 소개(선택 · 2,000자 — 비우면 없앰) · 연락처(숫자만 8 ~ 11자리)를 고치고 "저장"하면 검사해 틀린 칸 옆에 오류를, 맞으면 소개 · 연락처 저장(큐)을 보낸다.
4. 저장이 끝나면 내 업체 상세를 다시 읽는다 — 상단 바 · 대시보드도 같은 값을 본다. 다시 읽지 못하면 "다시 불러오지 못했어요" 안내.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `introduction` | | 업체 소개(2,000자) — 비우면 없앤다 |
| `phone` | ✓ | 업체 연락처(숫자만 8 ~ 11자리) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 소개 · 연락처를 고쳐 저장한다 | 저장(큐) 1번(소개 · 숫자만 연락처) → 내 업체 다시 읽기 1번 | ✓ 정상 |
| 연락처가 7자리다 | 칸 옆 "업체 연락처를 숫자만 정확히 입력해주세요.", 저장 0번 | ✓ 검증 실패 |
| "로그인 주소 복사"를 누른다 | 로그인 주소를 복사하고 "복사했어요" | — (공통 복사 버튼) |
| 영업중지 업체다 | 탭 위 위험 띠 + 사유 | — (그리기만) |
| 내 업체 상세를 못 읽었다 | "내 업체 정보를 불러오지 못했어요" · 다시 불러오기 | — (공통 빈 안내) |

## 2. 사진 탭 — `PAGE /manager/store`

**동작 흐름**

1. 업체 사진(5장까지 · 첫 번째가 대표 — 이용자 화면 지도 · 목록에 나온다)을 순서대로 보이고, 몇 장인지(3 / 5) 보인다.
2. "사진 올리기"로 JPG · PNG 를 고르면 업로드 주소 발급 → 파일 PUT → 사진 등록(큐) 뒤 내 업체를 다시 읽는다. 5장이면 올리기 칸이 꺼진다.
3. 손잡이로 끌어 순서를 바꾸면 그 순서(사진 ID 전부)로 순서 저장(큐) 뒤 다시 읽는다.
4. 삭제는 확인 창 뒤 사진 삭제(큐) 뒤 다시 읽는다.
5. 사업자등록증은 보기만 — 파일 이름 · 등록일 · "열어 보기"(비공개 파일이라 주소는 10분 동안만 열린다 — 지나면 다시 들어온다), 바꾸거나 지울 수 없다는 안내.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| 파일 | | 업체 사진(JPG · PNG) |
| `store_file_ids` | ✓ | 순서 — 지금 업체 사진 ID 전부(가장 앞이 대표) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 사진을 올린다 | 업로드 주소 발급(형식) → 등록(큐 — 키 · 이름 · 형식) → 다시 읽기 | ✓ 정상 |
| 끌어서 순서를 바꾼다 | 순서 저장(큐) 1번(사진 ID 전부, 바꾼 순서) → 다시 읽기 | ✓ 정상 |
| 사진을 지운다 | 확인 뒤 삭제(큐) → 다시 읽기 | — (입점 신청 사진 지우기와 같은 흐름) |
| JPG · PNG 가 아니다 · 5장이다 | "JPG · PNG 사진만 올릴 수 있습니다." · 올리기 칸 꺼짐 | — (공통 사진 부품) |

## 3. 영업시간 탭 — `PAGE /manager/store`

**동작 흐름**

1. 영업시간 카드 — "24시간 연중무휴" 스위치. 켜면 요일 표 대신 "24시간 연중무휴로 영업합니다." 한 줄, 끄면 일 ~ 토 7줄(휴무 스위치 · 여는 시각 · 닫는 시각, 닫는 시각이 여는 시각보다 이르면 "다음 날 02:00까지", 휴무면 시각 칸이 꺼지고 "휴무").
2. "영업시간 저장"을 누르면 휴무가 아닌 요일의 여는 · 닫는 시각을 검사해 그 요일 칸 아래에 오류를, 맞으면 영업시간을 통째로 저장(큐)한다 — 24시간이면 빈 목록, 아니면 일 ~ 토 7개(휴무 요일은 시각 없이).
3. 브레이크타임 카드 — 매일 같은 시각, 시작 ~ 마감 줄 목록(10개까지 — 몇 개인지 보인다), "브레이크 추가" · 줄마다 삭제, 마감이 시작보다 이르면 "다음 날 …까지".
4. "브레이크 저장"을 누르면 줄을 검사해 칸 아래 오류를, 맞으면 브레이크를 통째로 저장(큐 — 빈 목록이면 모두 지운다)한다. 서로 겹치면 받은 문구.
5. 저장이 끝나면 내 업체를 다시 읽는다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `is_always_open` | ✓ | 24시간 연중무휴(0 · 1) |
| `hours[]` | ✓ | 요일(0 일 ~ 6 토) · 휴무(0 · 1) · 여는 · 닫는 시각(HH:mm — 휴무가 아니면 둘 다) |
| `breaks[]` | ✓ | 시작 · 마감 시각(HH:mm) — 10개까지, 빈 목록이면 모두 지움 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 요일별 영업시간을 고쳐 저장한다 | 영업시간 저장(큐) 1번(24시간 아님 · 일 ~ 토 7개, 휴무 요일은 시각 없이) → 다시 읽기 | ✓ 정상 |
| 휴무가 아닌 요일의 닫는 시각을 비운다 | 그 요일 칸 아래 "휴무가 아니면 영업 마감 시각을 입력해주세요.", 저장 0번 | ✓ 검증 실패 |
| 브레이크를 하나 더해 저장한다 | 브레이크 저장(큐) 1번(줄 전부) → 다시 읽기 | ✓ 정상 |
| 24시간을 켜고 저장한다 | 빈 요일 목록으로 저장 | — (아래 영업시간 보낼 값 규칙) |
| 브레이크가 10개다 · 서로 겹친다 | 추가 버튼 꺼짐 · 받은 문구 | — (그리기 · 공통 실패 처리) |

**계산 규칙 — 영업시간 보낼 값** `toHoursDto`

검증: 24시간이면 요일 목록을 비우고, 아니면 일 ~ 토 7개를 차례로 보내며 휴무 요일에는 시각을 넣지 않는다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 24시간이면 요일 목록을 비운다 | 24시간 켬 · 7요일 시각 있음 | `{is_always_open: 1, hours: []}` |
| 요일별이면 일 ~ 토 7개를 차례로 보낸다 | 24시간 끔 · 7요일 10:00 ~ 23:00 | 요일 0 ~ 6 순서의 7개, 각 10:00 ~ 23:00 |
| 휴무 요일은 시각 없이 보낸다 | 월요일 휴무 · 시각 10:00 ~ 23:00 | 월요일 `{day_of_week: 1, is_closed: 1}`(시각 없음) |

**계산 규칙 — 다음 날 표시** `overnightLabel`

검증: 닫는 시각이 여는 시각보다 이르거나 같으면 다음 날까지로 알리고, 늦으면 아무것도 보이지 않는다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 닫는 시각이 이르면 다음 날까지 | `('10:00', '02:00')` | `'다음 날 02:00까지'` |
| 닫는 시각이 늦으면 표시하지 않는다 | `('10:00', '23:00')` | `''` |
| 같은 시각이면 다음 날 같은 시각까지 | `('10:00', '10:00')` | `'다음 날 10:00까지'` |

## 4. 운영 규정 탭 — `PAGE /manager/store`

**동작 흐름**

1. 영업중 카드 — 스위치를 바꾸면 바로 영업중 저장(큐) 뒤 다시 읽는다(끄면 영업시간 · 24시간과 관계없이 새 예약을 받지 않는다는 안내).
2. 정비시간 카드 — 퇴실 뒤 다음 이용까지 막는 분(0 ~ 240), "저장"이면 검사 뒤 정비시간 저장(큐).
3. 예약 · 환불 규정 카드 — 예약 가능 시작(1 ~ 4,320시간) · 100% 환불 마감(0 ~ 10,080분) · 마감 뒤 환불 비율(0 ~ 100%), 바꿔도 이미 받은 예약은 그때 규정이라는 안내, 지금 규정을 한 문장으로 요약해 보인다. "저장"이면 검사 뒤 규정 저장(큐).
4. 저장이 끝나면 다시 읽는다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `is_open` | ✓ | 영업중(0 · 1) |
| `maintenance_minutes` | ✓ | 정비시간(분, 0 ~ 240) |
| `booking_open_hours` | ✓ | 예약 가능 시작(이용 시작 n시간 전, 1 ~ 4,320) |
| `refund_deadline_minutes` | ✓ | 100% 환불 마감(이용 시작 n분 전, 0 ~ 10,080) |
| `late_refund_percent` | ✓ | 마감 뒤 환불 비율(0 ~ 100) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 영업중 스위치를 끈다 | 영업중 저장(큐) 1번(`is_open` 0) → 다시 읽기 | ✓ 정상 |
| 마감 뒤 환불 비율이 120 이다 | 칸 옆 "마감 뒤 환불 비율은 0 ~ 100% 사이로 입력해주세요.", 저장 0번 | ✓ 검증 실패 |
| 정비시간 · 규정을 저장한다 | 저장(큐) → 다시 읽기 | — (기본 정보와 같은 저장 흐름) |

**계산 규칙 — 규정 요약 문장** `policySummary`

검증: 예약 시작 · 환불 마감 · 비율을 한 문장으로 쓰고, 시간이 하루 단위로 떨어지면 일수를 덧붙이며, 비율이 0 이면 환불 없이 취소된다고 쓴다.

| 확인하는 것 | 입력 | 기대 결과 |
|---|---|---|
| 하루 단위 시간에는 일수를 덧붙인다 | `(720, 60, 50)` | `'이용 시작 720시간(30일) 전부터 예약을 받고, 시작 60분 전까지 취소하면 전액, 그 뒤 시작 전까지 취소하면 50%를 환불합니다.'` |
| 하루 단위가 아니면 시간만 쓴다 | `(36, 60, 50)` | `'이용 시작 36시간 전부터 …'`(일수 없음) |
| 비율이 0 이면 환불 없이 취소된다고 쓴다 | `(720, 60, 0)` | `'… 그 뒤 시작 전까지 취소하면 환불 없이 취소됩니다.'` |

## 5. 일시 예약불가 탭 — `PAGE /manager/store`

**동작 흐름**

1. 탭을 열면 끝나지 않은 일시 예약불가를 한 쪽에 20개씩, 시작 순으로 불러온다(시작 · 종료 · 메모 · 등록일 · 삭제). 없으면 "예정된 일시 예약불가가 없습니다.", 여러 쪽이면 페이지 탭.
2. 추가 카드 — 시작 일시 · 종료 일시(달력 칸) · 메모(선택 · 30자). "추가"면 일시를 "날짜 시각" 모양으로 바꿔 검사하고 틀린 칸 옆 오류를, 맞으면 등록(큐)한다. 겹치거나 지난 기간이면 받은 칸 오류.
3. 삭제는 확인 창 뒤 삭제(큐).
4. 추가 · 삭제가 끝나면 칸을 비우고(추가) 1쪽을 다시 불러온다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `starts_at` | ✓ | 시작 일시(YYYY-MM-DD HH:mm, 한국 시각) |
| `ends_at` | ✓ | 종료 일시 — 이 시각부터 다시 예약을 받는다 |
| `memo` | | 메모(30자) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 기간을 추가한다 | 목록 1번 → 등록(큐) 1번(날짜 시각 모양 · 메모) → 목록 다시 · 칸 비움 | ✓ 정상 |
| 시작 일시를 비우고 추가한다 | 칸 옆 "시작 일시를 입력해주세요.", 등록 0번 | ✓ 검증 실패 |

**계산 규칙 — 일시 예약불가 일시 글자** `toPeriodText`

검증: 달력 칸의 일시 값을 백엔드가 받는 "날짜 시각" 모양으로 바꾸고, 빈 값은 빈 글자로 둔다.

## 6. 문 연동 탭 — `PAGE /manager/store`

**동작 흐름**

1. 업체 총관리자만 이 탭을 본다 — 업체 관리자이거나 권한을 모르면(계정 쿠키 없음) 탭을 숨긴다(백엔드도 403).
2. 연결 카드 — 시크릿 설정 여부(설정함 · 설정 안 함) · 업체 ID, 원문은 다시 볼 수 없다는 안내(설정 안 함이면 "시크릿을 정해야 문 쪽 프로그램이 접속할 수 있습니다.").
3. 새 시크릿 카드 — 바꾸면 연결된 문 쪽 프로그램이 끊긴다는 주의 띠, 시크릿 칸(영문 · 숫자 16 ~ 64자), 버튼은 설정 안 함이면 "시크릿 정하기", 설정함이면 "시크릿 바꾸기".
4. 누르면 검사 뒤 시크릿 저장(큐) → 칸을 비우고 "시크릿을 바꿨습니다. 문 쪽 프로그램에 새 시크릿을 넣어 다시 연결해주세요." → 다시 읽기(설정함).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `door_secret` | ✓ | 시크릿(영문 · 숫자 16 ~ 64자) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 총관리자가 새 시크릿을 정한다 | 시크릿 저장(큐) 1번 → 칸 비움 · 안내 → 다시 읽기 | ✓ 정상 |
| 시크릿이 15자다 | 칸 옆 "시크릿 코드는 영문 · 숫자 16 ~ 64자로 입력해주세요.", 저장 0번 | ✓ 검증 실패 |
| 업체 관리자가 연다 | 문 연동 탭이 없다(탭 5개) | ✓ 정상 |
