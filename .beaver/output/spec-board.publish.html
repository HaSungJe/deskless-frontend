기준2xx · ALREADY_PROCESSED_PAYMENT 는 성공, IDEMPOTENT_REQUEST_PROCESSING · 5xx · 응답 없음은 잠시 뒤 다시, 그 밖 4xx 는 실패(401 · 403 · 본문 없음은 일반 문구)

입력 → 출력

  • (200, {paymentKey: 'pk', status: 'DONE'})→{state: 'ok'}왜: 2xx 는 승인 완료
  • (400, {code: 'ALREADY_PROCESSED_PAYMENT', message: '이미 처리된 결제 입니다.'})→{state: 'ok'}왜: 이미 승인된 결제 — 새로고침 · 다시 승인이라 성공으로 본다
  • (400, {code: 'REJECT_CARD_COMPANY', message: '카드사에서 거절했습니다.'})→{state: 'fail', code: 'REJECT_CARD_COMPANY', message: '카드사에서 거절했습니다.'}왜: 그 밖 4xx 는 다시 결제해야 하는 실패 — 토스 문구가 이용자에게 맞는 안내
  • (404, {code: 'NOT_FOUND_PAYMENT_SESSION', message: '결제 시간이 만료되어 결제 진행 데이터가 존재하지 않습니다.'})→{state: 'fail', code: 'NOT_FOUND_PAYMENT_SESSION', message: '결제 시간이 만료되어 결제 진행 데이터가 존재하지 않습니다.'}왜: 4xx 실패 — 결제 세션 만료도 토스 문구 그대로
  • (401, {code: 'UNAUTHORIZED_KEY', message: '인증되지 않은 시크릿 키 혹은 클라이언트 키 입니다.'})→{state: 'fail', code: 'UNAUTHORIZED_KEY', message: '결제를 승인하지 못했습니다.'}왜: 401 · 403 은 우리 키 문제 — 키 이야기를 이용자에게 보이지 않고 일반 문구
  • (400, null)(본문이 JSON 아님)→{state: 'fail', message: '결제를 승인하지 못했습니다.'}왜: 4xx 인데 본문을 못 읽어 보일 토스 문구가 없음
  • (409, {code: 'IDEMPOTENT_REQUEST_PROCESSING', message: '이전 요청이 처리 중입니다.'})→{state: 'retry', message: '결제 승인이 잠시 안 됩니다. 잠시 뒤 다시 시도해 주세요.'}왜: 같은 결제 승인이 아직 처리 중(두 탭 · 연달아 새로고침) — 끝난 뒤 다시 승인하면 같은 응답
  • (500, {code: 'FAILED_INTERNAL_SYSTEM_PROCESSING', message: '내부 시스템 처리 작업이 실패했습니다.'})→{state: 'retry', message: '결제 승인이 잠시 안 됩니다. 잠시 뒤 다시 시도해 주세요.'}왜: 5xx 는 토스 쪽 일시 장애 — 같은 결제를 다시 승인하면 된다
  • (null, null)(응답 없음)→{state: 'retry', message: '결제 승인이 잠시 안 됩니다. 잠시 뒤 다시 시도해 주세요.'}왜: 응답이 없어 승인됐는지 모름 — 다시 승인해도 멱등 키로 같은 응답
